## 1. 核心claim：保留用户原文

> 我们让VLA只学习task-space manipulation behavior，而不学习目标机器人的joint action；低层WBC独立学习广泛的task-space tracking。因此任务数据可以不依赖目标机器人遥操作，而同一冻结WBC能承接多个新任务。

上述claim从现在起是后续GR00T微调的**设计前提与待验证研究目标**，不是已经证明的实验结论。所有计划应服务于它；所有结果应分别说明哪些部分已有证据、哪些仍未实现。

**明确调整研究重心：把“简单轨迹生成/跟随”降为基础设施和低层qualification；把“如何构造、学习、闭环执行真正的object manipulation task-space trajectories”提升为GR00T主线。**

“因此”表达这套职责分离允许采用独立任务数据和复用低层控制的设计路线，不构成仅凭EEF接口就已证明数据独立、物理可行、多任务或跨本体成功的逻辑推断。

## 2. 已确认分工：我们不把师兄的WBC训练算成上层成果

用户已明确：上层团队从项目开始使用师兄提供的WBC，并在其冻结的基础上开发、微调GR00T。师兄报告后续版本主要提升性能、接口没有大改。

- 上层团队的主要研究对象是任务数据、GR00T任务空间策略、闭环任务行为及与冻结WBC的组合；不是重新训练一个WBC。
- claim中的“低层WBC独立学习广泛tracking”描述低层的职责和来源，不是授权上层团队现在启动WBC训练，也不是证明该WBC对任意轨迹均可靠。
- 同一轮高层比较及多个新任务的低层复用验证，绑定同一WBC权重、代码、配置与控制语义；不能为每个任务暗中微调低层或更换控制参数后仍声称完全冻结。
- 接收师兄新版时，明确记录版本差异并冻结新的执行器身份；不覆盖旧报告中的WBC身份或将旧结果改记到新版。
- 低层独立能力验证仍有必要，但主要属于执行侧qualification。它不应扩张为上层团队无止境的轨迹预训练项目，也不应成为任务数据准备必须等待的唯一前置条件。

## 3. 高低层接口与责任边界

```text
视觉＋语言＋实际EEF/夹爪状态
                ↓
       共享任务空间VLA策略
                ↓
   EEF XYZ＋rot6d轨迹＋夹爪命令
                ↓
  明确的坐标/时间/进度/安全接口
                ↓
       师兄提供的冻结WBC
       ＋独立夹爪执行通道
                ↓
     全身运动、物体交互与实际反馈
```

GR00T负责：选择语言指定物体和目标，规划接近／抓取／搬运／放置／释放等任务行为，根据实际观测处理进展、失败与恢复，并生成任务正确的未来参考。它不以Go2腿或ARX5关节动作、力矩、步态控制信号为监督目标；机器人关节、URDF、WBC隐藏状态不作为当前共享高层的私有补偿输入。

WBC负责：结合本体状态实现给定EEF参考，协调底盘、手臂、接触和平衡，处理已声明能力范围内的关节、速度、力矩、碰撞和扰动约束。它不读取隐藏任务答案来替GR00T选物体、走完路径或决定任务已经成功。

**实际TCP/EEF反馈与夹爪反馈必须保留。本体无关不等于开环、不等于删除“手实际在哪里”。** 视觉中可能存在本体外观，这也意味着不输入robot ID不自动构成跨本体证据。

复用现有XYZ＋row-rot6d和独立夹爪通道。当前H40、相对SE(3)编码、参考安装及空间预览的实际语义继续由对应固定protocol和运行绑定决定；本文不修改ABI、重定时、normalizer、精度或解码。单个短轨迹块不是整个开门／整理任务，多次观察与参考更新组成闭环。后续有必要改变表示时，须作为单独明确的科学干预，而不是把某种当前动作头形式当成不可改变的研究目标。

## 4. 数据独立：无需目标机器人任务遥操作，但必须有正确任务监督

当前没有真机数据，不阻断任务规格、仿真环境、算法教师和数据schema的准备。优先沿用已经整理的sim-first物体任务路线，不等待目标机器人任务遥操作才能开始。

推荐的数据边界是：**任务场景＋独立虚拟工具/夹爪＋任务教师 → 一致的RGB、实际EEF/夹爪状态、语言、正确未来EEF与夹爪命令。**

任务数据不得以“师兄的当前WBC必须先完整执行成功”作为生成或保留的前提。可以在独立任务环境中核验教师解法、物理接触、标签与安全；这种任务有效性检查不同于用目标WBC成功率筛选高层训练支持。目标机器人执行能力随后单独验证，其失败不能被回填为数据不存在。

后续数据必须覆盖物体状态变化，以及任务需要的夹爪开合、接触、阶段转换与恢复，不能用更多随机几何曲线或恒定夹爪占位标签冒充抓放任务数据。图像、实际状态和标签须来自同一时刻、同一场景；先按独立scene/object/episode划分，再切重叠窗口。教师命令与实际达到的动作分别保存。

仿真教师可以使用真值生成监督；隐藏物体目标、教师phase和成功标志不得泄漏到policy评价输入或在线执行逻辑。任务记忆、可观测阶段或学习到的终止机制可以成为未来单独研究变量，但本文没有授权新增它们。不得使用oracle成功信号停止、目标吸附或手工修改物体姿态伪造任务完成。

数据声明应准确写成“本项目任务适应无需新增目标机器人任务遥操作示范”。这不声称GR00T预训练从未使用机器人数据；用于标定或诊断的少量真实录播也不自动等同于任务示范训练。所有来源和实际用途分别披露。

## 5. 从现在开始的优先级

| 层级 | 工作 | 地位与交付 |
|---|---|---|
| 主线 | 物体操作任务规格、接触环境、算法教师、同步数据 | 让物体任务可定义、可监督、可复现 |
| 主线 | GR00T任务微调、语言条件选择、夹爪与任务恢复 | 学到任务正确的参考，而不只是曲线拟合 |
| 主线 | 学习策略的物体任务闭环及冻结WBC组合 | 评价物体是否达到任务要求、同一WBC是否承接新任务 |
| 基础设施 | processor/codec、姿态合法性、时序、轨迹连续性、安全门 | 保证任务链可用，不把修复本身等同于任务成果 |
| 执行侧qualification | 给定正确参考的跟踪、保持、底盘移动、负载／接触 | 证明WBC在声明范围内的能力，不转为GR00T主任务 |
| 有界诊断 | 简单到点、轮廓、局部反馈场及几何回归面板 | 保留已有证据并定位具体阻断，不自动无限追加 |

现役PI0274按原授权完成并保存有效结果；不因方向调整中断健康作业。其结果服务于物体任务中的反馈与恢复研究，不把“继续第N轮几何微调”作为自动后继目标。

**今后仅提出几何任务的GR00T新实验，必须明确指出它阻断哪一项具体物体任务、已有证据是什么、最小可辨识问题是什么、预算和停止条件是什么。单独“再降低XYZ RMSE”“再生成更多随机轨迹”不足以构成主线理由。**

任务准备现在优先，不要求先把全部几何诊断做到完美；这也不意味着让未获资格的高层策略直接控制无人看护的真机。

## 6. 物体任务与评价层级

首个落地候选沿用已有路线：语言指定的单物体抓取—搬运—放置—释放—撤离。之后根据实际结果扩展开放书架放置、简单铰链门及多物体整理。此顺序是准备方向，不是本文新授予的执行预算或成功承诺。

任务主要结果必须围绕物体／环境变化：物体是否实际抬起、搬至正确区域、释放后留在目标位置，门是否经接触打开至预定开度，整理是否完成正确对象分配。涉及移动操作时另报实际底盘位移和任务几何，不能用自由夹爪或机械臂可独立完成的例子冒充全身移动操作。

轨迹RMSE、反向输出、gate、局部场和首次到达均是必要时的诊断或约束，不替代物体任务成功；安全、失败、干预及旧能力保持继续独立报告。成功视频不替代全条件计数。单任务、多任务共享权重、各任务分别微调，以及人工/程序/学习规划器的角色应明确区分。

采用能分开归因的证据链：
1. 正确任务教师＋独立物理工具：任务和监督是否成立。
2. GR00T＋同一任务环境：高层是否真正学会物体任务。
3. 正确任务参考＋冻结WBC：本体是否能执行所需运动与接触。
4. GR00T＋同一冻结WBC：完整系统组合是否成立。

以上是评价设计原则，不是要求全部旧几何门通过后才能开始准备；每一项新的运行仍单独定协议和预算。记录高层raw reference、安装后的reference、实际achieved状态及物体结果。任务正确性、适配量、跟踪误差和最终成功不得相互替代。

同一冻结WBC承接多个新任务是需通过新增任务实验验证的claim。跨本体则进一步要求固定共享高层权重及任务数据；E0/E1数学执行器不是两个机器人。没有真机观测和试验时，只能声明相应仿真结果；同维接口、随机轨迹生成或无joint输入均不构成已证明的本体无关性。

## 7. 所有后续GR00T protocol必须有的主线对齐段

后续方案开头引用本章程的Decision ID、固定提交与Issue #11方向记录，并写明：

| 字段 | 必须回答 |
|---|---|
| `object_task` | 操作什么物体、语言要求什么、物体最终发生什么变化？若仅诊断，阻断的具体物体任务是什么？ |
| `high_level_contract` | GR00T的合法观测、EEF/夹爪输出与任务反馈是什么？ |
| `frozen_wbc_identity` | 使用师兄哪一份权重/代码/配置？本轮无WBC调用时也如实注明，不伪造接入。 |
| `task_data_provenance` | 标签如何产生，是否不依赖目标WBC成功或目标机器人任务遥操作？ |
| `single_intervention` | 本轮实际只改什么，哪些变量固定？ |
| `task_evidence_and_controls` | 物体成功、安全、失败与对照如何测；哪些只是离线/几何诊断？ |
| `budget_and_stop` | 前序复用、实际调用上限、停止条件和必须收口的产物是什么？ |
| `claim_boundary` | 本轮能支持哪些claim；哪些任务、真实执行与跨本体性质仍未证明？ |

这段用于把每个实验与用户目标对齐，不是增加一个需要反复等待的helper签字流程。不能为了满足模板编造未知值；缺失依赖和需要的下一决策直接写清。
