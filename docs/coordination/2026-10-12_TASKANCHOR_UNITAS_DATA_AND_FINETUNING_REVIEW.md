## 2. 论文实际贡献与我们要检验的问题

TaskAnchor针对task-state aliasing：相似当前观测可能需要不同阶段动作，或同阶段内需要依赖更早历史选择动作分支。方法以CA-TTT从历史读取视觉残差，同时预测由已完成milestone比例监督的语义坐标；经原视觉／语言入口条件化VLA，不替换动作生成器。训练语言使用真值坐标，推理使用预测；沿基础VLA原微调范围联合训练，并不表示所有基础权重永久冻结。推理时CA-TTT只更新并丢弃临时fast weights，不是在线用任务真值训练整个policy。

证据限制：论文主要在pi0.5与X-VLA上验证，不是GR00T或Go2。RMBench主表训练数据量不同，不能把约五倍提升全部归给adapter；同预算组件消融中coordinate-only 0.31、history-visual-only 0.18、两者0.68更具有针对性。并非所有任务都解决。

UNITAS官方材料支持：在每次交互内，用共同公制三维框架表示视觉、动作点运动与场景点运动；具有point dynamics expert和action expert，支持动作生成与动作条件场景预测，直接控制可以不生成全部flow。其价值不只是换旋转编码，而是动作与场景后果有可比较的物理表达。它不是已提供给我们的物理仿真器，也不是已经可直接下载使用的专家。

**本项目建议，非论文原结论：** 优先测试TaskAnchor-inspired历史／任务状态条件化；立即按UNITAS启发保存三维标定和物体运动监督，但把完整点世界模型放到后续。不改WBC，不把新论文benchmark成绩当作项目收益预测。

## 3. 我们的失败更适合哪些假设

PI0286同父模型／同1024更新：C0 TRAIN2/8，C1 TRAIN8/8、DEV5/16；没有新的独立确认。C1 first8 pooled XYZ RMS17.892mm反而高于C0的14.747mm。该结果说明固定训练任务成功与离线轨迹误差不等价，不证明任务状态是唯一根因。

C1 DEV漏斗为16请求、14持续抓取、12抓取且抬升、11前段历史齐全、5完整任务成功。285200最终hold41/41却缺抬升历史，285209到目标后离开；还存在早期抓握失败。可以据此提出任务历史、阶段转换、接触状态、几何和执行误差几类独立假设，不得把全部失败归因末端精度，也不能断言TaskAnchor一定修复。

真正要问的是：在同一合法动作接口下，当前观测是否足以区分应继续抓取、搬运、释放还是撤离？若不足，历史／任务状态是否提高实际决策？如果短任务的几何抓握仍错误，先解决覆盖、观测、标签和执行，而非强加长时记忆模块。

## 4. 数据先设计，再小批量生成；不等全环境搭完才想监督

建议并行复用已有Panda实际记录做离线历史／阶段审计，建设独立MuJoCo任务层。不要为研究记忆重新建设大型控制栈，也不要让师兄WBC是否通过全部跟踪门决定独立源任务数据能否成立。

数据身份分开：独立动力学夹爪／源Panda、目标几何下的独立任务执行、真实冻结WBC执行。独立工具必须有真实接触与有限驱动，不能瞬移穿物体／焊接抓取；固定base或工具源域成功不得称移动WBC成功。

从第一个正式episode保存以下原始记录，最后再切训练窗口：

| 数据组 | 记录 | 用途 |
|---|---|---|
| 合法当前观测 | 双RGB、实际TCP、实测gripper、语言、时间与有效mask | 原生GR00T输入 |
| 因果历史 | 完整顺序、episode起点、实际过去观测／执行 | 历史模型，不引入未来信息 |
| 动作标签 | desired EEF/gripper、planned H40、actually committed命令及其来源 | 监督；不以achieved冒充命令 |
| 任务事件 | 实际抓握、抬升、接触、释放、撤离、失败／重试边界 | 离线milestone／状态标签 |
| 三维观测几何 | 相机内外参及逐帧姿态、可选depth与visibility | 坐标一致性及未来几何学习 |
| 物体运动 | 物体局部固定点ID、位姿／关节、后续点轨迹 | 后果监督，不能作默认在线真值 |
| 执行溯源 | 源执行器／scene／teacher版本、requested/installed/achieved、时钟 | 对齐、归因、跨执行器比较 |

对象真值和成功信号可用作训练label／评分，不能直接作为Student线上输入。存下depth或object pose不等于原生GR00T自动使用它，任何新输入必须有明确接线与对照。

对刚体物体，点轨迹可由其实际位姿和固定物体局部点计算，不必在仿真中先引入不可靠视频追踪器。必须保持点身份和可见性一致；相机移动不能被误当物体运动。整个episode使用一致的公制任务／世界系，时间用物理秒，与执行阶段坐标分开。

三类关键覆盖：布局／视角等几何变化；同一场景不同语言目标；相近当前状态但不同真实历史和恢复需求。随机颜色和成千上万重叠H40都不能替代这三类独立支持。

成功专家与合格纠正suffix提供动作监督；失败轨迹可用于状态／后果label与诊断，不直接模仿错误动作。纠正suffix的合法历史可以包含之前真实失败观测，但动作窗口不得跨teacher接管、reset或失效参考边界。

## 5. 如何把数据真正变成有效微调

### 5.1 先做一次最小完整闭环

教师真实完成任务 -> 全episode记录 -> 独立split -> 原生codec与实际processor/collator -> 少量训练拟合 -> Teacher退出的物理闭环。先验证这条链，再扩大到独立布局和两任务数据。一个新的文件格式或READY脚本不等于实际可训练。

保留官方pretrained初始化、原生masked flow-matching、EEF10/H40和绝对gripper作为首个基线。冻结范围、模态、时间网格、统计量、decode、实际噪声和执行器版本明确绑定。新增历史/状态模块是声明的新干预，不在旧schema里偷偷填真值。

### 5.2 优先拆开的学习对照

B0：原生GR00T当前观测。
B1：同数据／初始化／优化预算，加入真实因果历史。
B2：相同历史和action链，再加入训练得到的task-state condition。

先做这组，不同时增加BASE head、点世界模型、视觉解冻与多种loss。History baseline不能省略；通用历史编码器只是TaskAnchor-inspired，不得冒称复现CA-TTT。若严格复现，则单独实现临时fast-weight更新和视觉token残差接入，并测量我们硬件上的真实延迟。

B2可采用 L_native_action + lambda_state L_state。训练milestone来自实际发生的事件，而非teacher发送命令或归一化时间。沿用论文训练真值／推理预测的方案时，必须单独报告预测状态闭环，而不能用真值状态评价。若训练-推理条件差成为问题，可另注册out-of-fold或scheduled predicted conditioning，明确是我们的改动。

仅在语言追加phase字符串、但没有重新微调和估计器，不是实现了TaskAnchor。只预测正确的阶段分数但动作仍错误，也不构成完整成功。

### 5.3 重试任务不能只靠单调进度

抓起后掉落时，ever_lifted仍为真，但currently_grasped变假。建议额外保存事件历史与当前谓词，必要时研究可回退／多维状态，不以时间或累计动作数量强制推进阶段。该设计是我们的恢复扩展假设，不是声称TaskAnchor已解决了所有重试语义。

训练顺序要允许取正确prefix构建记忆。独立打乱锚点可以，但不能丢掉对应历史而给所有样本空memory；不同episode不能串记忆。可以用冻结视觉编码器的缓存减少费用，编码器一旦更新，旧缓存必须失效。

采样按task -> data source -> behavior/event -> episode -> anchor，保留足够释放/撤离/保持；不再只看全段平均loss，也不把动态事件平衡本身当成已经解决（历史实验已尝试过）。

## 6. UNITAS启发的后续增量，而不是整套替换

先保留原EEF action head，研究小型动作条件的物体后果预测，或物体关键点运动辅助监督。由预测EEF确定的刚体夹爪点轨迹只是动作的几何重表达；真实物体运动才提供新增环境后果信息。

评估未来抓握/滑落/释放及对象位移时，必须条件化具体候选命令和当前可用观测。不能把尚未执行的actual achieved路径作为在线条件；不能给预测器未来物体真值。静态背景点不得主导指标，应分开报告动态物体、接触附近与静止点误差。

只有单一成功示范时，后果头可能只识别常见成功阶段。要检验动作因果敏感性，应在同一真实初态使用有界不同安全动作分支、真实执行和可辨识label；这须另行注册预算。先证明预测准确，再检验用于动作选择的闭环收益，不能用可视化好看代替物理成功。

统一点轨迹不自动满足ARX5可达性或四足平衡；WBC接口仍需SE(3)与gripper，不能直接传任意非刚性的点cloud作为EEF。不要在第一阶段用完整UNITAS重训取代GR00T，公开可运行资源本轮尚未取得。

## 7. 实施顺序与决策门（建议，不授运行额度）

1. 读取旧完整episode，建立真实历史/阶段错误与早期几何错误的分类；不重跑已曝光确认集。
2. 完成最小独立物体环境和teacher，完善上述原始数据schema；任务与WBC执行数据各自准入。
3. 少量样本端到端跑通记录、codec、native fitting与真实闭环；确认没有输入、时间或动作极性错误。
4. 固定布局、语言与split，扩大独立专家及真实恢复覆盖；B0/B1/B2使用同一数据和相同更新预算，避免adapter收益与多数据混淆。
5. 用未曝光初态评价完整物体任务、恢复、首次成功与持续保持；状态分类、XYZ/SO3和gripper误差只是诊断，不能代替任务成功。
6. 单任务有基本功能后，尽早加入T1抓放/T2堆叠及同场景不同目标语言，按每任务单列成功与旧任务保留。轻量历史依赖任务可用于机制验证，不立即扩展十几种任务。
7. 如果状态增强有效但空间／接触泛化仍受限，再做三维观测／物体后果监督对照；不要把所有输入输出和loss同时改动。
8. 上层源任务闭环与师兄WBC开发并行；将来同一冻结WBC分别执行Teacher和GR00T参考，单列目标组合与少样本适配。独立工具成功不是目标WBC或真机成功。

当前不应承诺这两项方法解决所有微调困难。最可检验的研究问题是：在冻结执行器和相同数据／训练预算下，显式因果任务状态能否减少重复、漏步、释放后漂移与恢复错误；进一步的三维动作后果监督是否提升未见场景物理成功。

## 8. Codex后续准备prompt（非新科学GO）

读取本研究备忘录、现有研究章程及PI0286封存结果；不修改师兄WBC或解除旧质量停止。先对已保存TRAIN/DEV合法数据提出全episode历史、物理milestone、三维标定/点身份、desired/committed/achieved分离的schema与测试设计，并明确现有文件是否支持。计划B0原生、B1历史、B2预测任务状态的配对训练；UNITAS只指导几何数据准备，不替换GR00T。不能将真值阶段送入正式Student评价，不能把Panda或独立工具数据称WBC执行数据。新采集、梯度、模型评价须另有固定预算协议，当前仅记录设计与代码改动清单。
