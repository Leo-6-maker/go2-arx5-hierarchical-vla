### Tier M — mandatory, immediate multitask EEF-motion preparation

These are three behavior/objective families, not three mature manipulation skills:

- **M1 REACH_POSE:** approach the language-specified visible target and requested orientation.
- **M2 ROUTE_AROUND:** reach a visible target through the requested side of an obstacle. Left/right paths must both be physically possible in the registered scene. The requested route, not merely target proximity, is part of success.
- **M3 TRACE_CONTOUR:** follow a visible closed contour in the specified direction, using continuous EEF motion. This evaluates trajectory shape and ordered progress, rather than one endpoint. Full-cycle completion is an episode property, not a requirement for every H40 window.

Color/object substitutions are within-family conditions. M1/M2/M3 share the same two camera streams, state ABI, robot, frozen WBC and EEF action interface. Task identity reaches the model through natural language, not a hidden task integer or oracle.

Use new, isolated scene namespaces. Procedural markers, contours, target regions and obstacles are authorized as new task assets. Do not alter legacy scenes or benchmarks. The robot geometry, mass, actuator limits, controller parameters, WBC weights, gains, gate profiles, physics timing and existing TCP convention remain frozen. Choose scene placements by analytic workspace/clearance checks before any outcome, never by trying many model predictions. No new robot attachment or dynamics tuning is authorized here.

### Tier C — preparation for genuine object manipulation

Prepare source-backed readiness specifications for **PUSH_TO_REGION** and **GRASP_LIFT_PLACE**. Identify actual object contact support, existing gripper geometry/joints/actuators, command transport and feedback, collision/material definitions, payload assumptions, observation channels and object-state success predicates.

Do not add a virtual weld, teleport an object, assume a constant gripper channel can grasp, or add unverified actuators to manufacture success. No contact-skill physical trials or controller/robot changes are authorized by this Tier-C specification. If an existing later implementation is found, index it and propose its isolated validation card for subsequent approval. Missing capability is `MANIPULATION_PLATFORM_DECISION_REQUIRED`, not a reason to stop the independent Tier-M data program.

This two-tier boundary explicitly replaces the misleading alternative of assuming that all desired manipulation tasks are already available. Motion-task generalization is a useful first stage, but future manipulation claims require separate real object-state outcomes.

### 4.2 New task predicates (never applied retroactively)

These are explicitly NEW pilot task requirements, not modifications of old TRAIN/CALIB criteria and not hardware-safety certifications:

- M1: achieved world-TCP position within 0.035 m and achieved orientation within 0.10 rad of the specified target, jointly sustained for 0.5 s; inherited cleanliness/termination rules also pass.
- M2: achieved world-TCP enters the requested side corridor in the correct approach-to-goal order, never enters the registered forbidden obstacle volume or makes forbidden contact, and reaches within 0.035 m of the goal for 0.5 s. Define corridor half-spaces/planes and margins from the frozen geometry; wrong-side arrival is FAIL even when the goal is reached.
- M3: achieved world-TCP covers all 12 registered contour sectors in the requested cyclic order, has cross-track RMS <=0.035 m over the registered traversal segment, and completes one full traversal within the task limit with no forbidden contact. Wrong direction and skipping sectors fail. Report p95/max cross-track error, progress and orientation separately. Sector crossing/hysteresis logic must be deterministic and unit-tested; no selecting the most favorable subsegment after the run.

Always report reference quality and actual tracking separately. Use the complete verified SE(3) native-to-world transform where required; test nonzero rotation as well as translation. No mixed native/world subtraction, subtraction of minima as tracking, or calling reference error actual TCP. Keep old erroneous statistics and verdicts historical; the new scorer has its own version/hash.
