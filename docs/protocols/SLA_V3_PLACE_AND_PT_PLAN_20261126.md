## 3. MAIN：先拆 PLACE 后半程，再决定修什么

### 3.1 四条 PLACE 全部列事件，重点看两条曾入区

每条轨迹在同 native tick／共同 frame 下对齐 raw、declared command、真正 consumed reference、actual 全身／物体，并记录 source phase。沿用 V2 已有工具，不另造事件控制器。

事件至少拆成：

1. 正确抓持与抬升；
2. **实际物体**进入目标区域，区分悬空被夹持与已有承托；
3. 原任务允许的释放条件、物体相对速度和姿态；
4. 模型全轨迹中 open／retreat 意图；
5. open 的编译、安装和实际消费；
6. 实际两指张开、物体脱离指垫、目标支撑建立；
7. 原稳定窗口内物体留在区域；
8. 机械臂安全撤离与完整终态。

先报告逐卡事件表，再决定事件之间是否构成嵌套漏斗。缺少逐卡关系时，不把 4→3→2→0 换算成 2/3 或 0/2 的条件成功率。

### 3.2 自主决策表

| 观察 | 本轮调整 | 禁止的替代做法 |
| --- | --- | --- |
| raw 有正确 open／retreat，转换、接续或替换使其丢失／延后 | 修证实的变换或进度 bug；若改变 P10，独立命名调度 profile | 吞掉模型真实张开、删除后缀、延长到任意时刻 |
| open 已实际消费，夹爪实际开度不符合声明 command | 核对 command 映射、驱动回显、实际接触及单位，修工程错误 | 加夹爪力、改摩擦、把 PT GRA 默认叠到 MAIN |
| 释放发生，但物体滑出／反弹，或撤离带走物体 | 查释放姿态、速度、支撑状态与 retreat 方向；区分模型意图、编译和实际跟踪 | 放宽目标区、稳定窗或安全门 |
| raw 本身缺正确放置、释放或撤离行为 | 启用独立 MAIN 动作侧后训练，补对应真实消费监督 | 让接口按 GT 阶段自动放手／撤离 |
| 同版本完整 Teacher PLACE 也失败 | 修 Teacher 构造或完整路径；确需改场景则另立开发条件 | 宣称学生失败全是模型能力问题，或把一次教师失败当不可达证明 |
| 先发生非 EEF 连杆接触 | 看实际 arm joints、base 与碰撞几何；仅凭 TCP 不能判断全臂可行性 | 用任意另求 IK 解替代原 WBC 构型作因果证明 |

发生在晚期的错误可能来自早期轨迹与观测分叉，故同时记录 earliest divergence 和 upstream contributors。四层局部诊断不自动等于完整闭环因果证明。

### 3.3 最短运行序列

1. **封存成功基线。** MAIN3.8K、原 L1、WBC／PD／solver、physics、安全、任务／scorer、reset、实际噪声与 N02 成功轨迹全部绑定。未发生改动不重复大规模核验。
2. **复用／补完整路径资格。** 先查 V2 两个 PLACE 条件是否已具备同版本资格；真实缺口最多补两张完整已知路径。
3. **最多两对机制诊断。** 原件和离线重编译不能回答时，选一个主要 PLACE 机制；第二对可用于另一个 PLACE 状态或 N03 接近问题。启动前固定唯一变量与可证伪预测。
4. **一个候选、四卡 PLACE 开发。** 两个预先绑定且完整资格的条件×两个新噪声，正常未抓持入口、单初始指令、原完整评分。无实质改动或新可判别假说时，不用同栈随机重跑找成功。
5. **必要的 N02 两卡回归。** 只有权重、共享执行、codec 或 clock 实际改变时启用。它是已知阳性回归，不是新独立确认。
6. **首成功后确认。** 候选冻结，三个未用于调参的新布局×两 seed，六卡小样本完整 PLACE 确认；任务和布局在新资格前封存，不因资格失败更换布局或降成 HOLD。

四卡开发须完整结算。候选在面板中出现共享身份／生命周期缺陷，停止受影响版本并保留结果，新版本另登记；不能中途换候选后拼成四卡成绩。

## 4. N01、N02、N03 分别如何处理

**N02：保存成功。** 原 L1 已经能完成任务，不因其它失败直接重构整套接口。有变更时做阳性回归；若没有变更，本轮引用封存证据即可。

**N03：作为开发难例。** 两个噪声都在抓前腕部连杆触块，提示共同布局机制，但还不能区分意图、工具映射、全臂构型或跟踪。检查碰撞前的原始姿态、腕／link6 扫掠与 base。若模型本身接近姿态错误，从 TRAIN 条件产生类似几何与恢复监督；不把 N03 测试轨迹直接回填 TRAIN。

**N01：先解释教师失败。** 区分缺依赖等技术错误、Teacher 路径构造错误、真实原门触发。一次资格不合格不能证明没有可行路径。修复后可用新 attempt 做资格，V2 的两格 NOT_STARTED 保留。若改变几何，则是新场景身份，不继承原 N01 的独立性。

N02/N03 和已查看的 PLACE 条件在 V3 调参后只能作开发／回归，不能继续称为 V3 未见确认人口。

## 5. MAIN 若需要学习，先查已有完整 PLACE 监督

历史合格教师集有 18 条红右 PLACE、19 条红 HOLD、20 条蓝 HOLD。[DATA] 它们是可检查的资产，不等于已被 MAIN3.8K 实际训练消费，也不等于与当前 mobile/L1 同合同。

先核对：

- 18 条 PLACE 在 MAIN 实际采样中的 episode／阶段暴露；数据目录里有不等于 optimizer 看过；
- 支撑／open／撤离以及抓后首 query 的唯一有效消费窗口；
- 原 command、frame、tool、基座行为与当前 L1 是否兼容；
- 数据是否包含学生偏离后的恢复行为，而非只有理想 Teacher 路径。

若 raw 缺终段技能而上述覆盖不足，启用 `MAIN_PLACE250_V3`：

- 父端点固定 MAIN3.8K；原输入与 COMMAND_REFERENCE codec 保留；
- 只训练已明确列出的 action expert／目标 IO 参数，视觉语言与其原 LoRA 冻结；精确参数名从原训练入口导出，不能靠“只训动作侧”一句话代替；
- 首选修正后的已有消费监督，缺口从 TRAIN 场景补；必要新 Teacher 数据首批最多 8 次生成尝试，失败全部保留；
- 按真实阶段分层，并包含保持既有 HOLD 的监督；阶段加权规则和参数范围在更新前固定，不能根据 DEV 临时改；
- 8–16 窗工程诊断的更新单独计数；正式从指定父开始，新 optimizer/RNG，固定 250 更新；
- LR、optimizer 和精度从 MAIN 可用 recipe 绑定为短试验；不直接沿用长训练的 warmup，必须在更新前检查 250 步内的实际 LR 曲线；
- 正式评价固定 250 的 raw 端点，不按中途最佳结果选步，不自动延长至 500。

如同时改变采样和参数范围，结论限于整个适配方案，不能声称单个因素已被隔离。若正确 raw 已有终段而执行未到达，则暂不训练，先修实际执行问题。

## 6. PT：停止无闭爪后缀的等待试验，推进有监督适配

### 6.1 新证据排除的范围

在保形、保值域的重定时下，38 份完整轨迹都没有的闭爪取值，不会靠延长消费生成。因此不再为“闭爪藏在这批未消费后缀”增加 SOURCE-END 卡。

仍须保留三个边界：

- 源闭爪阈值是源域诊断量，未必是目标实体闭合／预紧的充分必要条件；
- 该结论针对这 38 份输出，不代表所有未来观测、seed 和任务；
- 新调度可能通过改变后续观测影响后续预测，但不能把这种新行为混称为“消费到了旧后缀”。

先复用 V2 已核实的输入／源阳性／codec 结果，只补其真实缺口。接口正确、同任务 Teacher Pick & Hold 可行而意图仍缺闭合时，PT 适配按本节推进，不再等待 MAIN PLACE 或其它五模型面板。

### 6.2 本次代码审计发现的后训练准备缺口

本次实际读取了固定版本 `15396e863acb15590d76343104f5ce9a0174d931` 的源文件：

- `TargetExamples.__getitem__` 返回 `nominal_action`；它来自原 H40 nominal plan 的 H50 重采样。[LABEL]
- 消费证据另存在 `installed_reference_H40`、`confirmed_native_interval_mask` 和 `native_audit.jsonl.confirmed_native`。[LABEL]
- `right_arm_recipe.py` 的 `flow_inputs` 只屏蔽 7:14 以外动作维；`active_velocity_loss` 对所有 50 行计算右臂损失，没有消费时间 mask。[RECIPE]
- `teacher_sampling.py` 核实 P10 的实际消费与阶段采样权重，但没有把 reader 改为真实消费标签或向 loss 加时间 mask。[SAMPLE]

所以，**不能直接把旧准备 reader 的全 H50 喂入训练，并称为“实际消费 command 监督”。** 这是拟开展后训练之前必须处理的接口缺口。V2 更新为零，它不是 V2 失败已经由训练引入的原因；现场若已有后继修复，应先读回差异，不能把旧代码缺口强加给未读取的新实现。

### 6.3 本轮 PT 数据方案

优先从真实消费日志重建连续 command，再按当前 query 的原时钟／frame 生成 H50 标签；当前输入只取该 query 之前可见的数据，未来 query 的命令只能作为离线监督。不能跨 STOP、reset、缺失或未安装区间伪造连续标签。

无法覆盖完整未来窗口时，使用明确的时间×维度 mask；不要猜固定 15／16 行，也不要只在 loss 上 mask 而让未执行标签进入 noisy action 输入。具体算法和必要验证在 Runbook。

当前水果 pilot 首批准备最多 8 次 Teacher Pick & Hold 生成尝试，布局和 reset 在运行前列出；已有同合同完整合格样本可替代新生成。进入 250 更新的最低开发种子为至少 4 条完整合格回合、覆盖至少 2 个 TRAIN 几何布局，并覆盖正常接近、闭合、抓后反馈、抬升／保持。这个小样本门只用于短试验，不代表充分泛化数据；不足时诊断失败机制并登记下一有限数据批次，不无改动盲采。

释放／完整 PLACE 不是水果 Pick & Hold pilot 的数据前置。旧块体 57 回合可用于代码／mask 检查；不能暗中当作已经有的水果覆盖或未声明混合训练。目标图像、第三相机／缺失视角 mask、历史时钟必须与本次部署一致，不能盲用旧 reader 的虚拟左视角配置。

### 6.5 正式对照和继续规则

学习效果使用 **同一新 COMMAND codec 的 step0 与 step250**，在两个未入 TRAIN 的水果 DEV 布局、各两噪声下配对，共 8 卡。两臂使用相同输入合同、初态配置、统计、解码、L1、查询时钟、WBC、安全和 task；noise 张量实际核对。后续实时观测随各自运动自然分叉，不锁定或回放另一臂的观测。

官方冻结 PT 的旧 achieved/BTF/GRA 结果继续单列。若只比较旧官方 profile 与新 COMMAND250，结论只能是整个模型栈变化，不能把差异全归给学习。

- TRAIN 关键窗拟合不了：查 label/mask/load/梯度，再考虑动作容量；不立即解冻视觉。
- TRAIN 能拟合、DEV 意图不泛化：查独立布局、感知覆盖和恢复状态；不按 DEV 偶然好看选 checkpoint。
- raw 闭合／接近改善、native 不改善：返回执行／接触分析；不继续加步掩盖问题。
- 学生从正常入口完成自主 Pick & Hold：封存该分支，另登记新布局确认；不写成官方冻结 PT 的零样本成功。

## 8. 候选选择、确认与自主交付

MAIN 从已完整结算的开发面板选候选：先要求至少一次原完整 PLACE 成功、无未修共享实现缺陷；有多个就绪候选时固定顺序为“原权重＋证实的最小执行修复”优先，再“MAIN_PLACE250_V3”。这只是工程选择规则，不从不同任务人口的成功率评优。

若原系统无需任何修改就已有可复用完整 PLACE 成功原件，应核验后封存，不为凑实验制造变更。若四卡全失败，按最早缺口决定下一干预，不进入确认碰运气。

确认固定为完整 PLACE，其移动／底座进展谓词从 PLACE 原 spec 独立绑定，不从 HOLD 的 80 mm 自动推导。三个新布局先做 TRAIN／开发重叠审计，候选与任务冻结后再资格；失败布局保持 BLOCKED，不换容易布局。N01/N02/N03 的修复结果属于开发／回归，不能混入新确认。

日常工程依赖、编译、路径、记录、mask 和 reader 修复按现有项目授权自主完成。实际站点权限、资源可行性、旧 run 终态和单 owner 必须成立；不重开未知作业，不热补活动 capsule，不调 WBC／安全，不触发实机。

3. 实际改变的变量和下一决定；
4. 数据 episode／有效消费量、更新／完整端点、全部启动及资源终态。
