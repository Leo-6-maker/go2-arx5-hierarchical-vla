2. 采用现有Core owner、本地状态、锁与持久化日志，事前核本地模型/父权重链、Processor、环境、数据、缓存和输出。旧GLOBAL快照只作保守保护依据，明确非实时余额；不是新远程启动权限。不因跨站核账不可用阻止独立Core科学任务。
3. 同一GPU串行切换“训练→卸载模型/保存→推理评价→数据采集渲染”，不同时放两个大模型或边训练边跑渲染任务。其他用户进程不动；32GB总量不等于32GB当前可用。普通轻量CPU保存状态分析可在已有CPU许可内并行，不新建协调框架。

5. 不另迁训练平台、不重装现役环境、不启用TensorRT/量化/新RL来绕开本轮瓶颈；模型精度、图像分辨率、H40、Prefix8、评分变化都必须是单列实验，不能混入原比较。

## 3. 32GB上做什么，不做什么

### 已有原生证据的主通路

`scripts/pi0294/multitask/book_learning.py`已在Core实现：10,180,740个可训练参数（14张量），其他网络冻结，microbatch=1、gradient accumulation=32、有效batch32，AdamW 1e-4/WD1e-5，BF16 autocast；现有loader明确load_bf16=False。BF16计算不意味着全部权重/优化器状态都为BF16。book1024和recovery512证明这条通路可运行，而不是仅CPU mock。

继续复用父权重＋目标参数delta检查点，保留精确父链、Processor/statistics、optimizer/scheduler/RNG/cursor。约百MB的delta不是独立完整模型，交付时不得遗漏父权重。现有入口的24GiB空闲条件与所有真实设备要求先按原生检查；不能根据名义32GB直接忽略共享占用。

### 一次有界容量升级，而不是无限接口层续训

官方GR00T N1.7硬件指南对标准后训练给出40GB+配置；本项目book配方也明确约1.303B共享动作侧AdamW未被证明能与现有GPU用户一起放入Core。因此 **不把完整E2/全共享DiT训练作为32GB下的默认可行任务**。学习率、更多步数和显存是不同问题。

当保存诊断和新TRAIN支持扩大容量时，采用一个新的Core研究分支：目标接口＋实际模型中最后两个DiT block的明确参数白名单，冻结VLM/视觉及其余共享层。它不是原E2，也不复用原E2结果身份。先枚举真实模块名/参数数，不猜测不存在的LoRA CLI开关。

用同一双RGB/H40最长样本做10个实际optimizer更新（包括AdamW状态首次分配）、保存和恢复，记录allocated/reserved峰值、进程显存及真实空闲余量；建议保留约2–3GiB余量，但不是伪造已测显存。microbatch1/accum32优先；已有实现支持时才用非重入梯度checkpointing，并核验梯度和重载。若不适配，最多缩为最后一个block再测一次；仍失败则停止容量工程，继续数据/闭环路线，完整共享动作训练留至Vanda恢复。不为本轮另造分布式/offload/QLoRA框架。

显存通过后先一个固定512更新试验，同已声明的接口对照共用父权重、TRAIN、统计、有效batch、优化日程和DEV。若需要改变数值精度以腾显存，比较臂均采用同一新精度版本并注明不与原E2作严格等价比较。不能同时改数据、解冻范围、采样步数和速度过滤再归因于一个因素。

外部依据（当前官方指南，不是本项目实测）：https://github.com/NVIDIA/Isaac-GR00T/blob/main/getting_started/hardware_recommendation.md 。本地已验证实现及参数见 `book_learning.py`；不因官方40GB推荐否认本项目接口层原生训练可行。

## 4. 具体实验序列与出口

### M32-01 / P0：先解释recovery512首碰撞，不再直接加512步

使用已保存的book1024和recovery512原始记录，在各自首次偏离至停止区间对齐：实际输入、预测H40、真正安装的Prefix8、实际TCP、关节、书本、接触对与事件时刻。比较参考对应的全机器人几何和实际全机器人几何，报告最小余隙、跟踪误差、首点/跨chunk连续性、抓握阶段和接触来源。不同状态、阶段、数据/统计的模型不能直接用平均loss或运行时长排序。

分别检验：(a) 参考本身撞架或不按任务阶段移动；(b) 参考无碰撞但余隙小于实际跟踪误差；(c) 安装时钟/坐标/目标刷新有确定实现错误。只有(c)修实现并复用保存数据验证；(a)/(b)优先增加合法任务/恢复监督并测试动作侧可塑性。15.74微米接触不是取消安全门的依据，参考速度门通过也不代表轨迹可行。原book128/fit256/book1024/recovery512有效失败均保留，不为提高成绩改阈值、减时间或重新抽噪声。

**交付：**一张“首偏离—参考余隙—实际余隙—动作/跟踪—安全终态”表，以及只针对一个已识别机制的下一实验，不新建通用诊断平台。

### M32-02 / P0：数据从5个毫米邻域扩为有信息量的任务与恢复状态

先沿现有Teacher取得累计约15条、再视闭环需求增到20–30条完整TRAIN轨迹；这些是建议工作规模不是样本充分性保证或人工经费封顶。逐步变化可行的书本初始位姿、抓握偏移、接近方向，先验证工作空间/碰撞；厘米级平移和少量朝向变化作为待验证候选，不凭名称就宣称可行。不靠同一轨迹切更多窗充数，不把只改变±4mm的结果称跨场景泛化。

另外从学生在TRAIN开发初态真正访问的偏离状态，采集约10–20个不同恢复起点。专家从实际状态重新规划并完成后缀；只把真实已执行的专家命令作为监督，学生失败前缀不能改标签成为专家，未执行H40后缀不能入集。初始阶段失败较多时覆盖接近/抓取的纠偏，不只追加释放阶段。

原DEV10保留用于反复开发诊断，因已多次用于决策，不能称盲测。禁止把DEV episode或专家修正后的DEV后缀加入TRAIN；拟扩大空间范围时先保留新的20个未暴露确认条件，按完整初态/episode和场景谱系划分，不随机拆窗。设统一的新TRAIN统计并同时用于训练和推理；旧book5、E1/E2统计不覆盖。

**交付：**完整独立episode数、初态/几何/事件覆盖、专家后缀数、TRAIN/DEV/TEST谱系和数据版本，而非只有window总数。

### M32-03 / P0：一轮可解释学习与自主闭环

当前recovery512已经完成并失败，不再次当作“仍在训练”或原样重启。选定一个关闭的父权重，新数据/统计和预定采样策略，固定一次512或1024更新的后继；不因为Vanda离线就无限延长仅接口模型。可先用接口层建立新数据基线，再在M32-04内存资格通过时做同数据的小范围动作网络解冻对照。

建议起始任务采样：普通episode均衡，适当提高接近/抓取/支撑后释放等实际转换权重；恢复片段单独记录曝光，初始可用约25%恢复访问，而不是让几千稳态窗淹没事件。比例是新方案，不宣称已最优。原生masked-flow损失不变；更改统计时两条新比较臂共用统计，原recovery512只能当探索参考，不能作为纯恢复因果结论。

每个端点保存并实际恢复一次；先核固定TRAIN诊断的自由生成、动作门、阶段误差，再进行原独立DEV10。每个新端点可在相同DEV条件评价，但同一端点不重抽seed挑成绩。遇到原生硬安全停止按现有协议停该面板，明确报告“0/1＋9未运行”等分母，不写0/10；保留错误并在新开发版本修复。Teacher接管仅属于新训练数据采集，不能算自主成功。

**交付：**至少一个新checkpoint、实际任务成功数/完成数/未运行数、硬安全次数、接近/抓握/搬运/释放/保持事件和首失败原因。最低争取一次完整自主成功；DEV7/10及新确认16/20为目标而非承诺。连续多个端点只有TRAIN更好而闭环没有进展，就转数据/容量分流，不再只增加步数。
