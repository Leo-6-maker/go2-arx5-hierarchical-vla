## 0. 目标与优先级变更

**最终目标：一份共享GR00T上层policy，以双RGB、实际EEF/夹爪状态和语言为输入，输出EEF10/H40轨迹及夹爪命令，由冻结WBC承接，在Go2＋ARX5上完成抓放、推物、无锁柜门打开和单书指定位置放置。** 连续整理多本书属于后继长程组合能力，不以四个单技能的独立成功冒充。

主线为：**可信任务监督 → 真实模型后训练 → 真实源域闭环 → 同权重冻结WBC迁移**。源域策略可单独交付，但未通过目标域时，整机Goal不得标完成。

V7覆盖旧V6/TD10及各交接中的以下未来工作优先级：

- E1/E2是适配范围对照，不再是新技能采集和共享策略训练的强制前置；D25也不再是所有Core工作的必经排队门。
- 项目内部预算总额、逐小操作CPU秒、历史计划窗口和人工次数配额不再阻断新科研工作；每个作业仍有有限科学终点、有效站点权限和真实资源可行性。已有作业的封存配置/期限/费用不回写；后继使用明确新版本，不延长或复活旧作业。
- 取消“一个工程问题修一次仍失败就整个研究分支永久封禁”的未来开发规则。允许证据驱动的多轮修复；同一故障无新证据重复时必须换诊断或实现，不是无限盲跑。
- 清理由用户负责；Codex不再扩大checkpoint删除、磁盘清扫或凭据维护。

**不覆盖：**真实硬件/碰撞/关节安全、站点配额与权限、唯一任务所有者、未知副作用不得重放、数据真实性、原封存比较的科学定义。历史STOP/失败/账本/有效端点保留。目标自由机身S1/T2安全隔离不因本文件解除。

同时保存预测参考、实际安装命令、实际EEF、物体结果和首次失败阶段。有效拒绝也有信息价值；启动工程失败不等于策略失败。首个条件完成后批量完成同一就绪模型的原面板，不为每个条件再建一套身份/预算框架。E1/E2正式对照最后各用原24，E2未完成则诚实写待测，不能阻塞V7-03/04。

### V7-03：以物体任务成功建立监督，工程修复可以自主迭代

**放书先处理已知参考几何缺陷。** 在物体坐标系联合搜索抓取深度/接近方向/腕姿/夹爪开度/预放置位姿，不只把抓点上移固定距离。用原机器人和实际夹爪、书本几何检查全段IK连续性、关节余量、扫掠碰撞；区分允许的指垫接触与link6/掌部/书架非预期接触。单点IK和张开夹爪扫描不等于闭合抓持路径通过。阶段推进依实际抓握/物体状态，不依固定计时。先得到一条完整原任务示范，再测5–10种不同初态；开放台面放书只能另立较简单任务，不能替代原指定格成绩。

旧PORT05 STOP和旧放书安全停止保留。**V7明确允许源域仿真的证据驱动后继开发版本：记录缺陷与预测，修复原代码，必要静态/单元检查通过、旧actor已终态后，用新run在原安全监控下验证；不必每次问人类GO。** 必须有实质变化，不能改PORT编号重跑同一缺陷；这不解除目标自由机身S1/T2安全隔离，也不授权实机。

### V7-04/05：尽早实训与闭环，不等先凑满300条

每项新技能先有5–10条不同初态的完整种子；复用现有合格抓放/推物数据，不机械重采。先冻结一个小数据版本和未参与优化的DEV配置，打通实际GR00T读入、loss、自由生成及闭环。如果小样本不能拟合，可用8–16个明确关键窗口做一次有界诊断；不要以所有离线误差接近零作为允许闭环的前提。

第一份新技能checkpoint允许只包含已具备合格监督的技能，明确标记部分能力；最终共享版本必须覆盖四项任务。第一轮在10个固定DEV完整条件上记录成功、动作拒绝和阶段失败，不承诺成功率。只有接口/标签正确而TRAIN不足时才研究优化或动作侧容量；专家状态好、学生偏离后失败时补恢复监督；DEV随新场景增加而改善时再扩量。

沿用现有共享配方作为起点：同一raw父和NEW_EMBODIMENT槽位；共享动作侧适配，原生masked flow matching；初始冻结语言，视觉策略单独版本化；双RGB/EEF10/H40不变。当前候选AdamW LR1e-4、WD1e-5、有效batch32、总日程10000/warmup500，以2000/5000/10000作记录端点，可先在2000闭环再决定接续。**这些是新任务配方起点，不是已验证最优值或不可改变的资金上限；不得把更改后的试验混回E1/E2固定对照。** 修改配方须在新run前写明假设和DEV，保留旧结果，避免同时改多个无法归因因素。

数据先扩至50抓放/50推物/100门/100书的300条候选pilot；必要时累计150/150/500/500。数量以独立episode、布局、物体实例、事件覆盖和恢复状态计，不把重叠窗口当独立样本。版本间共享种子谱系要披露。新统计仅用TRAIN拟合；E1/E2原R0不改，正式TEST不参与采样/选模。

**新共享版本的工程pilot验收设计：** 冻结同一权重/处理器/解码/安全与任务判据，在每技能20个预先留出的完整场景条件上评价，共80次；每技能至少16/20，评估中硬安全违规0，全部失败保留。该阈值是V7提出的交付标准，不是成绩或80%总体下界保证；报告区间并披露小样本与预训练污染未知。若沿用已有更大的已封存TEST，不得事后缩小到20挑结果。发布模型、配置、数据版本、失败表和推理说明；不能只交成功视频。

### V7-06：源域成果不冒充整机成果

源policy与目标执行资格独立。目标S1/T2事故先取得根因及安全修复证据；现有自由机身安全隔离不由一次源Teacher修复解除。目标后继运行需单独安全放行，WBC权重、增益、代价和求解器仍冻结。成立后评估同一高层权重，不以目标数据调过的权重冒充零目标数据迁移。

目标试验分别报告高层决策、安装/时序、实际跟踪与物体结果。若源域通过而目标未通过，交付“可用源policy＋目标阻断”，最终整机Goal仍未完成；不要让目标失败抹掉源域结果，也不要让源域成功掩盖目标失败。

## 3. 减少防御性编程：具体替换，而非口号

| 现状中的低效做法 | V7要求的最小实现 | 保留什么 |

| 每个小修都重算完整历史、重读全部大权重 | 权重/数据转移后完整校验一次；按不可变版本与已验证manifest复用，变更范围增量验证；身份不可信时才重做全核 | 科学输入一致性、实际数据完整性 |

| 同一次启动重走多层重复schema、路径深度、旧run字符串断言 | 在入口集中验证身份/必要字段/路径归属；科学数值严格，非语义元数据允许兼容；同一结果供下游复用 | 数据类型/单位/形状/原任务身份，不能吞异常 |

| 35秒RPC同时承担SSH、全账校验和写入，失败再建新分支 | 连接/远端进程期限/结果读取分别设计；依据实测耗时留余量；只读可有限退避，未知写必须先查效果再处理 | 网络失败不能推断零效果；不把延长超时宣称根因已解决 |
| 管理owner在长队列等待中反复全历史检查耗尽软时限 | 原作业生命周期内低频查询、持久状态和明确接管；修正项目自设管理限额 | 平台权限和反重复调度；不杀他人/健康作业 |
| 每次异常增加新family、专用closeout/授权类 | 尽量在现有owner/记录器/同一评价器中修复通用缺陷；归档旧版本，收敛接口，不再复制一套账本 | 历史证据、已有物理控制与评分 |
| 大批CPU fixture通过后仍未调用真实模型 | 触及的单元/回归检查＋一项最小原生冒烟；共享底层大改/发布前再全套 | 原生结果与mock明确区分；不为了减少测试漏掉关键安全测试 |

不要求先完成整个平台重构。先对阻断当前一次模型前向/episode的接缝做最小修复，并立刻验证。只有发现通用重复故障才提炼公共函数。禁止新增与当前交付无关的预算分配器、审批状态机、全历史复算框架或“证明自己已经证明”的多层回执。

上述为待实现设计，不是现役代码已被删减。正在运行的capsule不热补丁；旧onceIO/registry的已知与未知操作必须兼容收尾。新profile可以简化流程，不能另建影子canonical账本绕过锁和原结果。

## 4. 自主修复矩阵与异常处理

**无需再次人工批准：** 本项目应用代码中的路径/别名/序列化/类型/迁移兼容/超时/owner生命周期/恢复保存/入口路由修复；隔离用户环境内的依赖纠错；最小资源配置与节点选择（限既有许可）；源域Teacher参考、抓取几何、明确版本的场景接入错误；无成功语义变化的日志/评分实现bug。每次写明缺陷、改动、预期观测，做受影响检查后可以直接发起新的有限开发验证。形式评分bug修复需新评分版本和保留旧分数，不追溯伪造旧PASS。

**需要独立安全/权限决定：** 目标自由机身T2安全隔离解除、实机动作、WBC或安全阈值变化、共享基础设施/挂载/SSH/凭据/系统服务、他人GPU任务、删除用户成果或新外部付费采购。用户负责清理；不能把运行受阻当sudo许可。真实显存不足不能通过关闭OOM检查或偷换量化/分辨率解决。

**重试规则：** 确认未提交的只读或准备动作可在修复后接续；写入/任务启动结果未知时先独立查runID/进程/队列/文件，禁止盲重发；已完成的有效正式评价不重跑挑结果；科学开发失败允许修复后新版本验证。连续两轮同一症状而没有新机制证据时，暂停该实现路线，做保存状态分析或换独立路线；不是全项目永久STOP，也不是无限重试。

**最小运行记录：** 每run只需要已有manifest（版本/输入/任务/seed/有限终点）、实际日志与产物、终态/评分/消耗。优先复用现有记录器和普通状态；不为每个Python函数创建lease。费用归实、失败保留，旧账有未决但与新独立任务不存在资源或身份竞争时，不把全历史完全收敛强行变成全项目门槛。
