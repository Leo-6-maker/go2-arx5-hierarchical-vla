**有，而且已经能从代码中指出几处具体的不对齐。但目前没有发现“旋转矩阵乘反了、动作被反归一化两次、Flow Matching符号写错了”这类足以直接解释全部失败的低级错误。**

更核心的问题是：

> **SLA正在学习一个“近似专家的动作序列”，而我们的执行入口要求它输出一个“起点、时间连续性、首尾速度和整段运动约束都符合规定的控制参考”。这两个目标尚未被完整连接起来。**

此外，**我们现在的C20训练配方与SLA官方后训练配方存在实质差异**，尤其是action expert的更新范围。不能把当前结果理解为“已经按官方方法充分后训练，SLA仍然不行”。

本次主要对照了C20实现 `efae461c`、后继诊断代码 `750011df`，以及项目锁定的官方SLA版本 **`405ca8879c032a05f0a778adc7d86f4e221c5eba`**。我做了静态代码核查和CPU数学复现，没有运行新的GPU训练、模型生成或原生仿真；当前13次评价的完整数组及C20统计文件仍未在本环境取得，因此下面会区分**代码中已经确认的问题**与**需要实测判断贡献的因素**。

## 一、先给结论：哪些层已经对齐，哪些没有？

| 层次 | 核查结果 | 判断 |
|---|---|---|
| 预训练权重加载 | 主干与接口参数按shape严格加载；新增参数限于LoRA，不是随机重置整个动作头 | 未发现明显加载错误 |
| Flow Matching基本公式 | 加噪、目标向量场、时间分布和attention构造与锁定官方实现一致 | **核心公式已对齐** |
| EEF旋转与相对动作 | 使用 \(R_kR_0^\top\) 编码，解码为 \(\exp(\Delta r_k)R_0\)，与官方SO(3)实现一致 | 未发现乘法顺序错误 |
| 图像、state、归一化 | 主要路径复用同一resize、tokenizer、quantile与codec | 静态上基本一致，需补不同计算路径的数值检查 |
| **H40时间与边界语义** | 专家具有连续规划状态；学生自由预测40点；认证器又隐含首尾零速 | **存在明确合同差异** |
| **训练目标与物理约束** | 训练优化归一化动作FM误差，执行按物理速度／加速度硬拒绝 | **存在明确目标差异** |
| **可训练参数范围** | 我们采用VLM LoRA＋action expert LoRA；官方RoboTwin使用VLM LoRA＋完整action expert | **没有复现官方配方** |
| **控制历史可观测性** | 专家用历史速度、滤波状态和夹爪时钟；学生主要看当前图像与离散化状态 | **可能存在条件信息不足** |
| 训练／推理数值设置 | 训练显式使用`highest`精度，推理函数未在同处显式锁定 | 需要定点核验，不宜直接认定为根因 |

前四项的依据分别在权重加载、批量FM、codec与官方变换实现中。它们不能证明整套系统绝对正确，但足以避免继续把所有精力放在重复检查shape、hash和保存恢复上。

## 二、最重要的发现：H40认证检查的边界，与真实滚动执行边界不是一回事

涉及两个关键文件：

```text
world_model/fusion_trajectory_adapter.py::_geometry
world_model/task_learning_grasp_v1.py::FiftyMsProgram.validate_envelope
```

### 1. 认证器给速度序列首尾补零

当前平移检查的核心代码是：

```python
velocity = np.diff(rows[:, :3], axis=0) / 0.05
acceleration = np.diff(
    np.vstack((np.zeros(3), velocity, np.zeros(3))),
    axis=0,
) / 0.05
```

旋转加速度采用同样的首尾补零方式。也就是说，认证器除了检查内部曲率，还要求：

\[
\frac{\|v_0-0\|}{0.05}\leq0.25,
\qquad
\frac{\|0-v_{38}\|}{0.05}\leq0.25.
\]

因此，虽然平移速度上限写的是 **50 mm/s**，首段和末段受到加速度条件影响，实际只能不超过：

\[
0.25\times0.05=0.0125\ \mathrm{m/s}
=\boxed{12.5\ \mathrm{mm/s}}.
\]

这是代码中的实际约束，不是模型训练loss里显式表达的要求。

我用相同平移差分公式做了CPU合成测试：

| 合成轨迹 | 内部加速度 | 认证器最大加速度 | 结果 |
|---|---:|---:|---|
| 20 mm/s匀速 | 约0 | **0.40 m/s²** | 拒绝 |
| 7.5 mm/s匀速 | 约0 | 0.15 m/s² | 通过 |
| 7.5 mm/s轨迹，三个相邻点加入±0.2 mm误差 | 0.32 m/s² | **0.32 m/s²** | 拒绝 |

第三个例子整段位置RMSE只有约 **0.055 mm**，仍然不能通过加速度门。

所以，**“模型轨迹看起来很接近专家”与“满足当前执行协议”之间，确实可能差得很远。**

这里也要避免另一种过度判断：末端补零并非完全没有执行含义。`eef_document()`会在40点之后再重复末点，形成41点wire参考，因此尾部保持确实属于当前协议。**问题不是现在直接删除首尾检查，而是必须明确：这是带停止边界的参考合同，不只是一般的轨迹平滑检查。**

### 2. 它检查“假定零速的起点”，却没有直接检查真实参考到第0点的连接

还有一个更值得重视的细节：

`_geometry()`的速度来自`np.diff(rows)`，**没有将当前anchor或上一条已消费参考加入速度差分**。

函数虽然计算了`max_anchor_distance_m`，但`FiftyMsProgram.validate_envelope()`只检查速度、加速度等指标，没有用这个量约束第0点与当前参考的连接。 

因此，下面两条轨迹在这层内部差分检查中结果相同：

- 40点全部停在当前anchor；
- 40点全部停在距离anchor **10 mm**的位置。

二者内部速度与加速度都是零。后一条的起点偏差会被记录，但**不会因此被这层包络检查拒绝**。

而wire转换设置的是：

```python
start_delay = 0.
lead_in = 0.
```

所以不能认为这条参考在安装前已经由该函数完成了真实历史接续。下游WBC或安全监测可能进一步处理或发现问题，但这不是当前H40检查已经证明的内容。

**这形成了一处不对称：**

> 认证器对假设的首尾零速度很严格，却没有在同一层显式验证真实历史参考与预测第0点之间的连续性。

这可能同时带来两种现象：某些持续运动被入口拒绝；某些内部平滑但起点有偏移的预测进入控制器。**当前那一次碰撞是否与此有关，尚不能仅凭代码确定。**

### 3. 专家天然满足的结构，学生只是“尝试拟合”

连续专家构造的名义轨迹第0点就是当前实际EEF，经过参考变换后第0点就是当前参考。跨query速度与滤波状态由专家保留，P10结束时才提交。

学生则自由生成40个动作点。即使训练标签的第0点始终是零相对位移，**当前生成器并没有硬性保证第0点必须为零，也没有硬性保证它与上一段速度相接**。

因此，这不是简单的“坐标系又错了”，而是：

**专家的输出具有确定性的边界结构；学生的输出表示没有保留这种结构。**

这应是下一阶段最优先明确的执行接口问题。

## 三、“nominal和installed都检查通过”没有我们想象中那么强

当前安装位置为：

\[
p_k^{installed}
=
p_t^{reference}
+
p_k^{nominal}
-
p_t^{actual}.
\]

对同一query而言，后两项中的anchor都是常量。因此：

\[
p_{k+1}^{installed}-p_k^{installed}
=
p_{k+1}^{nominal}-p_k^{nominal}.
\]

也就是说，**installed与nominal的内部平移速度、加速度完全相同**。

旋转安装也是固定旋转左乘，内部相对旋转的角度范数相应保持。当前分别检查desired与reference，主要验证的是同一段内部几何在两种表达下没有发生意外变化。

它并没有额外证明：

- 与上一query的真实速度连续；
- 与当前实测运动状态一致；
- WBC能够动态跟踪；
- 接触过程中不会发生碰撞。

**因此，“全量标签通过完整编译器”仍是必要条件，但不是控制可执行性的充分条件。** 下一轮报告应将“内部包络”“真实接缝”“动态跟踪”分开，而不是继续只报一个`full_H40_pass`。

## 四、我们与SLA官方的训练配方，确实有重要差别

这一点以前的讨论关注得不够。

### 1. 官方RoboTwin不是双LoRA配方

锁定版本的官方配置是：

```python
paligemma_variant = "gemma_2b_lora"
action_expert_variant = "gemma_300m"
```

其freeze filter明确将action expert排除在冻结的VLM主干之外。我们则配置：

```python
paligemma_variant = "gemma_2b_lora"
action_expert_variant = "gemma_300m_lora"
```

并用正向allowlist，只训练：

- LLM中的LoRA参数；
- `action_in_proj`；
- `action_out_proj`；
- `time_mlp_in/out`。

这意味着，**action expert的大部分dense权重以及不在allowlist中的内部归一化／调制参数保持冻结**。   

官方该变体中，VLM LoRA rank为16，action expert LoRA rank为32。**这不是完全不训练动作专家，但确实比官方示例限制了它的适配自由度。**

| 配置 | 官方RoboTwin示例 | 当前C20 |
|---|---|---|
| VLM | LoRA | LoRA |
| Action expert | **完整训练** | **LoRA＋外部投影／时间接口** |
| 空间监督 | 开启，权重0.5 | 关闭 |
| EMA | 0.999 | 当前链未维护EMA |
| 数据增强 | 对齐训练预处理 | `train=False`预处理 |
| 更新／batch | 30K／256 | 1K／32 |
| horizon | 默认50 | 40 |

官方配置、EMA更新和空间loss路径都可直接核对。  

**这不证明完整action expert一定解决当前失败。** 但它说明我们不能跳过“是否限制了新动作语义的可学习性”这个问题，直接认定必须改WBC或重新设计世界模型。

尤其我们同时改变了单臂任务、夹爪latent、时域、参考接口和移动观测分布，动作专家需要适配的内容并不少。

### 2. `train=False`不等于没有训练

这点必须澄清。

当前`error32()`调用：

```python
preprocess_observation(..., train=False)
```

但外层仍然使用`jax.value_and_grad`计算梯度，并更新参数。这里主要关闭的是图像增强，而不是关闭反向传播。 

它可能影响视觉泛化，但**不能据此说我们之前1,000步是“假训练”**。

同样，部署时移除空间projector也不是错误。官方`Pi0Align`继承基础`Pi0`，增加的是训练期对齐loss，采样沿用基础模型。真正的差别是我们当前后训练没有继续空间监督，而不是推理时漏运行一个必需的教师网络。

### 3. 更值得做的是action expert更新范围对照，而不是一次打开所有官方选项

若当前C20在专家输入上也明显欠拟合，我建议优先比较：

**同一C20_1000父模型、同一数据与统计、同一访问和noise：**

- 控制臂：继续现有PEFT；
- 干预臂：保留现有adapter，额外解冻action expert的dense与相关内部参数。

两臂保持相同初始函数、相同新增预算，避免一边重置模型一边改变训练范围。先不同时打开EMA、空间loss、图像增强和新轨迹表示。

这能回答一个比“再加500步”更清楚的问题：

> **当前失败是否部分来自动作专家适配自由度不足？**

## 五、损失空间与物理空间没有对齐，夹爪尤其值得检查

### 1. Flow Matching公式没有写错，但它不约束机器人导数

我们批量实现中的：

\[
x_\tau=\tau\epsilon+(1-\tau)a,
\qquad
u_\tau=\epsilon-a
\]

以及Beta时间采样、attention mask和输出投影，与官方代码一致。**这里没有发现正负号或目标方向写反。** 

但\(\tau\)是生成过程的时间，不是机器人H40每点50 ms的物理时间。因此，向量场拟合得好，不自动保证动作序列的一阶、二阶差分满足限制。

这也是为什么目前要同时记录：

**active7动作误差、物理速度／加速度误差、边界误差和任务推进量。**

### 2. 7维动作补到32维不是bug，但总loss容易误导判断

当前loss对32维都取均值，分别记录active7和padding25。官方也使用固定动作维度上的FM误差，因此不能仅凭“25维padding”就判定实现错误。 

不过，对我们的单臂任务来说：

\[
L_{\mathrm{FM}}
=
\frac{7}{32}L_{\mathrm{active}}
+
\frac{25}{32}L_{\mathrm{padding}}.
\]

所以总loss下降，不一定意味着有效动作块已经达到物理可执行精度。也不建议未经验证就把padding loss全部删掉：这些维度仍参与动作embedding和生成过程，修改后需要新的配方身份和对照。

### 3. 一次sigmoid解决了范围，没有解决夹爪速度

当前夹爪顺序是正确的：

**反归一化latent → sigmoid一次 → nominal-to-mechanical映射一次。**

没有发现重复sigmoid。  

但有界不等于变化率有界。

若统计分位数覆盖开闭端点，对应logit大约为±9.21，那么在夹爪半开附近，一个仅**0.03的归一化预测跳变**，可以产生约 **54.9 mm/s**的机械开度速度，超过当前40 mm/s限制。

这个数值来自合成计算，**是否适用于C20实际分位数必须读取`STATISTICS.json`确认**。它提醒我们：如果12次拒绝主要是夹爪速度，继续只分析XYZ曲率会找错方向。

## 六、还有一层容易被忽略：学生看不到专家用来保证连续性的全部状态

当前配置为`pi05=True`。官方π0.5实现中，state通过离散文本token进入前缀，而不像π0那样再通过连续`state_proj`进入动作suffix。我们的Tokenizer也只取有效7维，然后使用官方tokenizer。 

官方tokenizer把归一化状态离散到256个bin。

因此，当前模型实际得到的是：

**单帧双相机＋语言＋离散化的EEF／夹爪状态。**

而成功专家还依赖：

**前一参考、速度、内层滤波速度、角速度、夹爪关闭起始时刻，以及阶段历史。** 这些信息在采集记录中存在，但不进入学生。 

这形成潜在的条件信息差异：

> 相似的当前EEF和图像，并不必然对应相同的参考速度、夹爪进度和下一段合法接续。

这不是说SLA一定需要直接读取专家内存。正确的研究选择有两种：

**一种是让执行适配器承担确定的边界连接职责**，高层预测操作路径，不必精确记住底层参考速度。

**另一种是给高层有限的、部署可获得的历史**，例如上一段实际参考、当前参考误差或观测历史。

不能把专家goal、物体真值、阶段标签和滤波器隐藏状态直接塞给学生，然后称为自主策略。

此外，量化精度也值得检查。某个状态维度如果TRAIN分位数跨度为0.20 m，一个bin约0.78 mm；这并不能单独证明量化导致失败，因为视觉也能提供信息，但与当前亚毫米级二阶差分余量放在一起看，**不能默认离散state足以支持所有精细接缝预测**。

## 七、哪些“对齐问题”目前可以降级，哪些仍需补测试？

### 已有较强代码支持、暂不应反复怀疑的部分

**SO(3)编码顺序正确。** 我们和官方都使用左相对旋转 \(R_kR_0^\top\)，不是Euler角直接相减。CPU随机旋转往返的最大矩阵误差约 \(8.9\times10^{-16}\)，但这只是数学检查，不替代现场TCP标定。 

**quantile公式一致。** 都是相同epsilon的仿射归一化，不做隐式输出裁剪。新统计来自TRAIN变换后的latent，导出器还用实际学生编译器验证标签。 

**图像预处理与缺失相机mask基本一致。** 两条路径共用`images224()`，缺失第三视角显式mask；uint8到[-1,1]由官方`Observation.from_dict()`完成。没有看到二次缩放到[-1,1]的代码错误。 

**H50改H40不是天然的权重shape错误。** 官方horizon本身可配置，当前加载仍检查实际参数shape。它改变了学习和执行的时间含义，但不能单凭40与50不同便认定预训练权重失效。

### 必须补的，是“训练向量场”与“部署采样向量场”的数值一致性

当前训练显式使用：

```python
with jax.default_matmul_precision("highest"):
    ...
```

推理的`sample_actions()`则没有在同一位置显式设置相同精度。是否受到外层全局配置补齐，需要查实际运行环境；源码局部差异不等于已经证实数值错误。 

更重要的是：

- 训练使用prefix＋suffix的一次完整前向；
- 采样使用prefix KV cache，再逐步运行suffix；
- 现有RGB16恢复比较，大部分是同一采样路径前后是否一致。

因此，恢复一致不能覆盖全部计算路径。

建议固定同一`observation、xτ、τ`，直接比较：

1. `error32`对应的训练向量场；
2. 官方完整前向的向量场；
3. 缓存prefix后的推理向量场；
4. `highest`与实际部署精度下的差异。

比较应落到**有效7维、反归一化后的物理量及导数**，而不只检查张量shape。

新PR #391的16条输入核对与48窗口诊断已经覆盖了一部分工作，应该运行并读取它的真实结果，不再重复写同一种检查。需要补强的是上述**向量场级数值对照**。

---

## 八、我建议怎样修改研究顺序

### 第一优先：先让12次拒绝说清楚自己失败在哪里

直接使用当前诊断代码，交付：

**通道、首个超限点、峰值／阈值比、首尾或内部、P10内外、nominal/reference、预测第0点到真实参考的差距。**

新诊断已经可以区分`START_REST_BOUNDARY`、`END_REST_BOUNDARY`、内部与后缀，并记录first-point gap。不要继续只用统一的`H40速度／加速度拒绝`汇总。

同时，单独分析碰撞，不能提前将它归因于首点跳变或旧F2底座下坠。

### 第二优先：按结果选择一个干预

| 诊断结果 | 优先干预 |
|---|---|
| 大量失败来自首点／真实接缝 | 新版边界条件化轨迹表示或明确执行适配合同 |
| 专家输入上也严重欠拟合 | **现有PEFT vs 解冻action expert** |
| 点误差小、内部二阶差分大 | 同数据的物理时间导数监督／结构化轨迹对照 |
| 主要是夹爪速度与开闭事件 | 夹爪时间表示与监督，不盲目修改XYZ |
| 专家状态合法，学生状态失效 | 部署可得历史与专家纠正数据 |
| 训练／部署向量场不一致 | 先修数值／输入接缝，零新增训练 |

对于边界条件化表示，原则是：**在模型定义和训练标签中明确起点、必要历史与终端条件，而不是评价时临时把失败轨迹裁剪或平滑。** 它应是新策略版本，旧raw与JOIN10结果保留。

对于完整action expert实验，保留同一个C20父模型和相同初始函数，只改变可训练参数范围；不要同时更换normalizer、空间loss和BASE head。

### 第三优先：最后才是扩大数据

C60可以继续作为安全范围内的数据积累，但它主要增加既定局部条件的重复经验。**如果当前模型在专家状态上都不能生成合法H40，单纯扩大相似示范不是最有辨识力的实验。**

现在尤其没有理由把问题直接归为WBC能力不足：已经有成功专家轨迹，而且12次学生失败发生在任务空间认证入口。也没有证据表明必须引入RL才能解决。

---

## 最终判断

**确实有“没对齐的层”，但最重要的不是神经网络某两个隐藏层接错了，而是以下四个接口没有形成一致合同：**

\[
\boxed{
\text{专家的有状态连续计划}
\;\not\equiv\;
\text{学生的自由H40生成}
\;\not\equiv\;
\text{认证器的首尾停止假设}
\;\not\equiv\;
\text{真实滚动参考历史}
}
\]

同时，我们实际训练的是**SLA预训练初始化下的受限PEFT版本**，并没有复现官方完整action expert后训练。这是必须控制和研究的配方差异。

我的优先建议是：

**先完成当前12条失败的边界／内部／夹爪分类及向量场一致性检查；随后在“边界条件化”和“解冻action expert”中，按证据选择一个最小对照。不要同时改五个因素，也不要继续仅靠C60/C100规模增长判断问题会自动消失。**
