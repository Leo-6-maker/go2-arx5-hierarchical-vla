# D4 多源后训练 · C20 迁移对照

第一轮固定 A、B 两臂。A 从已校验的官方 SLA_base 直接训练 C20。B 从同一基础权重开始，仅导入封存 S1000 的 20 个共享 LoRA 数组，再在同一 C20 上训练。两臂均重新初始化 Adam。B 的源任务历史成本单列为 1,000 更新、32,000 访问。

C20 使用 20 条已有 Go2 HOLD 专家轨迹、1,376 个原窗、冻结统计和已核对的 50 ms 前一实际夹爪命令。目标保持 G7 单臂、body/wrist 当前 RGB、H40 和同一 G7 解码。两臂各 500 更新、16,000 目标访问、0 源访问。每步 B32/micro4，保持绝对 cursor 的采样、噪声、flow time 和状态 token dropout。目标 FM32 加四个完整十步生成的辅助梯度，XYZ 和夹爪速度权重均为 0.1。

B 首次更新前，逐项对比 87 个 step-zero 数组。其余 67 个数组逐位匹配 A，20 个共享数组与 S1000 索引逐项匹配。目标动作输入输出、源时序 MLP、优化器和统计按各域的既有身份处理。每臂固定 96 条 C20 TRAIN 诊断、87 个全态数组恢复和独立进程普通 RGB16 复现。每臂 2,000 次训练内完整生成，另有 12 次梯度资格生成、96 次端点生成和 16 次独立复现。

第一轮使用一个现有站点绑定的 GPU，两个训练进程串行。服务器托管等待复用原 GPU owner 锁和实际显存／主存要求，预留完整两臂的执行时长。期限跟随站点既有分配。保留有效负结果、原 D3 进程和原 M2 资格。

## 目标域评价

闭环前需完成两臂封存、普通 RGB 恢复、未使用场景身份核验和新原生执行规格。首个开发面板拟使用 F1、F2 各两个新的场景，同一场景固定全部六条 HOLD/PLACE 语言指令。两臂匹配场景、重置和随机数，预先固定顺序，共 48 个科学请求。分别计完整 HOLD、H40 拒绝、首次非法接触，以及 PLACE 的正确物体抓持、20 mm 抬升、入区、稳定支撑、释放与撤离。用同场景换目标与换区域的匹配差异检查语言响应。已封存历史记录只用于诊断或数据身份核对。首轮 A/B 的 PLACE 属于零目标 PLACE 示范迁移。

逐条审核历史完整 PLACE 的原生判分、分割和场景身份、当前 RGB、H40 与消费掩码、实际夹爪命令时钟以及 FP32 压力检查。通过者可进入未来独立探索 TRAIN，并与新 DEV 和 TEST 做场景和采集 lineage 去重。原 M2 的联合 G7/QUAL48 资格照原协议执行。

## 后续联合实验

C 使用目标 C20 与已封存的 RoboDojo TRAIN。D 在完成有限 LIBERO 抓取、搬运、放置数据审计后独立实施。域内保留帧、时钟、动作标签和掩码。RoboDojo 保留双臂 H50 的未来记录参考语义，LIBERO 保留原动作、夹爪、观察和终止定义。候选共享 LoRA，使用独立域 I/O、动作归一化和监督掩码，目标控制辅助项只在 Go2 域计算。

首轮 C／D 可预注册每步 24 目标与 8 源访问，同时构建等更新数的纯目标对照及实际目标访问数匹配的对照，分别报告 GPU/CPU 时间和实际访问。训练与数据接入由届时固定计划和现场资源控制。
