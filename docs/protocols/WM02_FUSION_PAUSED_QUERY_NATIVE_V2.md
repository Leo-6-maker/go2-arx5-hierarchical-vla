# Paused native capture and one frozen target query

This is a new HOLD-only native phase, not a motion policy, a new physical
permission, or an executed online qualification. The old query readers, old
task predicates, failed receipts and active capsules remain unchanged.

`collect-target-fusion-paused-query-v2` uses the original AUTO1/P1 worker,
registry, locks, finite leases and frozen C10 executor. Its exact endpoint is
3703: original initialization to2503, then48 actual50ms HOLD atoms. Every atom
retains original full-preview certification, receiver ACK, source-relative
TTL, solver-target consumption, gripper packet/consumption and native safety.
It never installs a VLA proposal or a WM correction. The original400ms steady
prefix screen is assessed before capture. A genuine full1 slow-trajectory
predecessor with complete trace, safety and clean shutdown is required.

The separate native and GPU scopes are both registered before either starts.
The immutable pair manifest fixes both roots, common source, native output and
3703 boundary, task/scene/frame hashes, query UUID, checkpoint, seed and finite
deadline. GPU spec pins the completed native spec bytes; CPU spec binds the
pair and GPU path, avoiding a circular spec hash. The native recipe check calls
`preflight_pair` before physics. The bridge rechecks before one actual capture.
It creates no registration, worker, service, queue or execution grant.

CPU EGL Mesa renders the current measured packet. A one-use atomic readiness
marker follows complete snapshot validation. The already admitted GPU worker
waits for that exact producer, checks current memory again and invokes the
same frozen official model/processor and original `ResidentModel.generate`
once. H40 remains complete, already decoded once, without clipping or relative
accumulation. After the GPU job closes, the native bridge validates actual
worker/result/spec/model/observation/action identities and checks the actual
simulator is still paused with unchanged packet, quota and source clock.
Waiting never rebases a reference TTL. It then cancels the HOLD reference and
closes the original native process normally. An unknown/failed scope is
reconciled, never replayed or treated as a new draw.

This first operation is **capture + query only**. It proves neither sequential
VLA control nor physical benefit. Cold loading, snapshot wait, inference and
capture-to-return wall time must be reported separately from native simulation
time. A paused simulator is not a real-time robot controller.

## New task and score binding

`fusion_short_skill.task_document(scene_sha256)` defines the new task
`FUSION_TARGET_RED_CUBE_APPROACH_STEP_V1`: “Move the open gripper a little toward
the red cube, then hold without touching it.” It binds the actual compiled
scene and canonical hash of the new score. This task does not relabel the old
target shadow, source T1, old contact task or old BASE predicate as successful.

The prospective approach-step score uses actual target-world measurements.
Its precontact point is fixed at120mm from the initial cube center along the
initial cube-to-TCP ray. It requires at least2mm signed progress and distance
reduction, lateral drift at most3mm, excursion at most25mm, each finger at
least38mm open, object displacement at most0.5mm, base displacement at most2mm
and base rotation at most0.5degrees. Final400ms TCP diameter must be at most2mm
and speed at most25mm/s. Original native safety and no robot/object contact
remain required. These are declared task-score conditions, not replacements
for native safety thresholds. Continuous metrics and all failed predicates
are retained. Passing this step is neither precontact arrival nor pick/place.
Object truth is scorer-only and is not added to the policy observation.

The HOLD/capture/query operation sets `task_executed=false`; it never calls
this movement score to manufacture task success. Before a future same-frozen-
GR00T comparison, inspect the actual new prompt's H40 and qualify its complete
adaptation/action domain. Do not assume the old archived calibration H40 or
its one-direction response model covers a different proposal. Only then
declare matched adaptation and with/without-WM physical short-skill conditions.
No task Actor/Critic or weak-ARX distillation is introduced.
