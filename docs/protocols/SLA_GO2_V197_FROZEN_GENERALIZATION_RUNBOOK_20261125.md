## D. 源时间、查询与终末

### D1. R0 的 SOURCE-END

一份模型返回从 0 至 49/30 s 的全部源区间经原编译器连续执行；到真正消费完源尾后，在原合法 P10 边界查询。收到了后缀、编译了后缀、预览安装了后缀，都不等于已消费。

native dt=2 ms；atom=25 tick=50 ms；P10=10 atom=0.5 s。P10 是物理消费窗口，不能误作 10 个 30 Hz 源行。沿用原重发、TTL、序号与接收器，不用本计划另建协议。

禁止通过检测目标高度、开爪、将来成功事件来选择查询点或保留片段。此次不启用 V196 已失败的早刷新配置作为默认。

### D2. 因果闭环的最低证明

至少两份官方返回各有正 SOURCE 区间被实际消费：
- 第一份在本回合真实交接／初始观测上生成。
- 第二份在第一份实际 SOURCE 消费后的新 native tick 观测上生成。
- 两份均有正 SOURCE 的实际 EEF／夹爪命令接纳与消费，ALIGN／BRAKE／dwell 不满足该要求，不能只完成网络请求。第二份已有正 SOURCE 消费后才允许闭环成功终末。
- 不要求像素 hash 必须变化；不以虚构运动填历史。
- 任务事件与后续策略消费分别记录。第一份就完成的事件可记录为单 chunk 事件；没有第二份有效消费时不能称本计划的闭环合格成功。

### D3. 停止与评分时间

记录 `first_task_event_tick`、`first_qualified_interval_end_tick`、`first_failure_tick`、`terminal_tick`。任务成功谓词可以触发现有合法终末，但不能截断未消费的物理命令来倒填成功。

保持 1 s 必须是原生实际积分期间的状态，不能计暂停墙钟或终末无新增积分。若成功事件之后、合法终末之前触发原安全，则记录“曾达到任务事件，终末失败”，不靠成功短视频覆盖。

原 gate violation 的首次 tick 与最终 HOLD tick 可以不同，都保留。原 receiver 无 STOP 时不伪报接触 STOP。终末后新增参考安装／接纳、时钟授权／积分均为零；实际 worker／租约收尾确认。UNKNOWN 写效果先独立查明，禁止盲重试。

所有以下真值仅供 scorer／原安全使用，不返回到模型或链接层目标生成。继承现役有效抓持定义，不发明一个更宽松的接触计数替代。

### E1. T / T_MARK

令 p0 为交接实际物体 XY，b 为登记蓝目标（或语言指定标记）XY，u=(b−p0)/||b−p0||。初态有非退化目标距离，否则该条件初始化无效。
- progress = (p(t)−p0)·u ≥0.020 m；
- distance_reduction = ||b−p0||−||b−p(t)|| ≥0.015 m；
- cross_track = ||(p(t)−p0)−progress*u|| ≤0.010 m；
- 物体 z(t)−z_reset≥0.020 m；
- 以上与实际抓持连续满足1 s；全过程原安全。

u 是 scorer 变量。链接层不能用它投影动作、控制 Z 或把物体直接拉向目标。T_MARK 是新的语义任务，不能混入旧 T 的比例。

### E2. L 与 CH 的放置段

为避免“空中丢下后落稳”被误记为受控放置，在首次形成持续释放的边界检查：
- 物体与原允许支持面真实承托接触已经成立，按原真实接触判据，不能只用包围盒或高度接近代替；不新增力控制阈值。
- 物体最低点相对支持平面的有符号间隙绝对值≤3 mm，同时原接触安全全部成立；该容差不放宽原门。
- 物体竖直速度绝对值≤0.020 m/s。
- 释放定义为双垫均无物体接触，实际 pad gap 比handoff增加至少0.006 m，并持续满足最终稳定窗；不强求全开时仍有接触。

最终1 s连续窗口：
- 真实原允许支持接触成立；
- 两垫均脱离，pad gap增量仍达标；
- |z−z_rest|≤0.003 m，质心速度≤0.010 m/s；
- L 的 ||p_xy−p_handoff_xy||≤0.020 m；CH 的 ||p_xy−p_blue_mark||≤0.020 m；
- 原安全和因果闭环成立。

z_rest 来自本场景原reset的实际稳定桌面状态；不在看到结果后改成落点高度。先出现短暂接触消失又恢复应记录 transient loss；取最终连续稳定释放的起点作受控释放判定，同时保留早期掉落。若早期已发生未受控空中掉落，不能以后恢复把该卡改为“全程受控放置”。

### E3. CH 的阶段作用域与逐布局资格

CH初始蓝标记候选：G00为名义水果reset XY+[0,0.060]m，G01为+[0.060,0]m；场景hash与各布局完整运动/支撑/释放范围在模型输出前绑定。已有QT/QL/QGG的实际覆盖可复用，不足则QCH00/QCH10补相关资格。G01不得从G00自动继承；预定场景不合法则该条件未启动。

评分器顺序锁存H→T→L，各达标窗口非重叠。H使用初始handoff z；H的1s同时达标窗结束时记录p_H作为T的水平起点，并在评分器计算朝所指mark的单位向量。T要求相对p_H新增20mm、目标距离减少15mm、横偏≤10mm、离原桌面静置基线至少20mm并真实抓持1s。T窗结束后才开始L最终窗评价，L用原reset z_rest与蓝标记位置评分。H/T阶段不允许失抓；L正确主动释放不受独立H全回合保握规则约束。

这些锁存与基线只在scorer；模型从头至尾收到同一整体prompt、同一GRA和真实连续历史，不收到阶段切换或目标坐标。独立H中失抓后重新抓起单列恢复结果，不与持续保握H混算。

## H. 逐卡结果与归因

每张卡保留三条主数据：原SLA物理意图；实际安装且消费的command；实际EEF、夹爪、物体与原门。关键失抓用同一native时间轴连接：

raw/decoded g → consumed source phase → GRA command → receiver ACK/consumption → actual fingers/pad forces → contact loss → object motion。

力的采样／坐标系／法向定义随实际实现记录；不能把命令差直接称为牛顿。没有可用力日志时标缺测，不伪造。

| --- | --- |
| MAPPING_PRELOAD_LOSS | 意图保持但映射实际卸载，接触／力随后下降；排除或披露位姿同时变化 |
| POLICY_OPEN_BEFORE_PLACEMENT | 实际消费的张开先于非允许释放，映射／执行合同合格 |
| GRIP_EXECUTION_FAILURE | 合法已消费保持命令没有得到对应夹爪／接触响应 |
| POSE_OR_LOAD_SLIP | 夹爪意图保持，滑移与位姿／载荷变化有关；只作机制候选，勿宣称唯一因果 |
| SOURCE_PHASE_STARVATION | 完整输出含后段但刷新反复阻止实际消费 |
| STANCE_LIMIT | 原脚漂移门率先终止；记录阈值与原tick |
| QUALIFICATION_BLOCKED | 对应资格不足，学生没有启动 |
| TASK_TIMEOUT | 原生／墙钟／查询有限端点到达仍未完成 |
| TECHNICAL_INVALID | 无法解释政策能力的初始化、接口或记录故障 |

`terminal_reason`与`mechanism_tags`分开；多机制并存时报告UNKNOWN或MULTIFACTOR，不逼迫唯一根因。原门触发是有效系统失败，不自动丢到技术invalid。工程中止前若已有效消费，应保留部分证据，并按实际原因报告外部截断或技术无效，不能吞掉成本。

报告至少三种分母：success/registered及coverage；success/valid；全部starts/physics/forwards/updates。registered为具体合同/profile/名册已封存并启用的科学面板，启用后成员不可按结果删除；全部86张是有条件容量，未启用后继、未定合同的N任务另报计划覆盖。资格、诊断、学生与离线前向分别计数；一回合42次前向不是42个独立样本。不同profile不混算。按前序正例触发的T确认等必须披露选择，分开报首轮与后继。

同一profile的确认面板不按前两张得分替换后两张；预登记的T确认触发条件可以决定是否展开。安全／技术问题停止面板时保留未完成人口，修复后新版本另计。
