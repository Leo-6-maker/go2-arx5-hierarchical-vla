## 1. 十天到底交付什么

**主目标A：一份共享权重的GR00T衍生策略，在声明的近场工作域内，根据双RGB、原合法语言和实际EEF/夹爪反馈，经冻结WBC，在自由机身Go2+ARX5上完成T1抓放与T2推物。** 本轮只承诺努力实现并测量这一目标，不承诺十天一定成功。

**独立交付B：同样严格验证的固定底座源域policy。** B成立、A未成立时，结论必须写“源域可用；整机目标未完成”，不能把B当A交差。若只有单任务成立，写“单任务pilot”，不能宣称共享双任务policy。若两者都未成立，交付可复算负结果与已定位瓶颈，不发布可用声明。

本轮默认是已有MuJoCo物理闭环，不是实机部署。带物理暂停的因果闭环可以支撑仿真任务结论，但不能称实时策略或实机安全认证。W1/W2移动、EEF13学习、柜门、第二本体、完整新WBC训练、完整72格目标数据效率研究，均不放入十天关键路径。

## 3. 科学主线：每一步只回答一个问题

```text
专家标签与动作契约一致吗？ ── 否 → 一项语义/时间修复，不先训练
          │ 是
实际processor能保住这些语义吗？ ── 否 → 修处理链，旧结果保留
          │ 是
模型在精确TRAIN关键状态上学到了什么？
          ├─ 学不会 → 最多一次16窗口有界拟合诊断 → 选择一个优化/容量因素
          └─ 能生成合法动作 → 源域实际闭环：接近→接触→任务结果
                                      │
                专家状态好、执行后差 → 实际TRAIN失败状态的合格恢复监督
                                      │
                              冻结一个共享policy
                                      │
冻结WBC的可信Teacher任务资格 ────────────┤
                                      ▼
                     同权重W0迁移 → 新独立人口盲测
```

高层学习与目标执行资格是独立证据线；目标Teacher不成功不阻止源域学习，源域尚不完美也不阻止有限目标Teacher资格。它们共享Core时必须排队，不能同时争抢GPU/物理进程。

**科学闭环的单位：问题 → 固定输入 → 有限干预/测量 → 实际结果 → 明确分流。** PR数、测试数、模型文件数不算科研里程碑。一个有判别力的负结果可以关闭任务，但不等于policy已可用。

## 4. 小任务阶梯：从可观察动作走到完整任务

下面是诊断阶梯，不是另造一套在线状态机替VLA决策。学生继续收到原T1/T2语言；没有新监督就不凭空新增“reach/contact”等训练指令。

| 闭环 | 具体观察 | 出口与失败后的唯一方向 |
|---|---|---|
| L0 标签闭环 | 专家实际提交/安装参考→同一切窗/时钟/动作门 | 标签本身可执行或得到精确不一致；不得用任务成功视频替代 |
| L1 表示闭环 | 物理专家动作→实际训练processor→实际推理解码 | XYZ/SO(3)/夹爪/首点/时间保持；有损clipping单列，不以改门解决 |
| L2 生成闭环 | 固定观测/实际noise→自由生成H40→专家/物理指标 | 识别拟合不足、条件响应不足或轨迹非法；不只报flow loss |
| L3 接近闭环 | 从合法home或已记录开发状态，执行前缀并再次观察 | TCP朝合法接触区域推进；记录原参考、安装参考、实际反馈；不算任务成功 |
| L4 接触/推送闭环 | T2中真实接触、物体方向/位移、停止后结果 | 先在3个预选开发几何观察完整T2，再收齐6个；不以EEF到位代替推物成功 |
| L5 抓取/释放闭环 | T1接触、真实抓持、抬升、搬运、开爪、撤离及保持 | 逐事件定位首次偏离，最终仍须原T1完整评分 |
| L6 完整共享策略闭环 | 同一几何两条语言，完全从共同home执行 | 共享权重完成T1/T2；不允许任务专属Teacher或隐藏真值接管 |
| L7 执行域迁移闭环 | 同一policy分别在源执行器和冻结目标WBC运行 | 区分模型原参考错误、安装/消费错误、实际执行偏差 |
| L8 独立确认闭环 | 冻结之后打开新20几何并完成完整分母 | 通过第1节，或明确未通过/工程不完整；不再调参 |

优先完整episode中提取这些事件。只有现有工具已支持完整物理状态恢复且安全合格时，才用专家中间状态做条件化诊断；不能为了诊断再建一个恢复系统，不能将这种容易的起点混入完整任务分母。小任务可证明局部能力，串起来后必须重新证明整体能力。

## 5. 可直接分派的任务卡

每卡只交一个小结果包：`RESULT.json`、必要曲线/表、原证据索引。复用已有合格证据即可标`REUSED_VERIFIED`；没有产物则`NOT_RUN`，不能用CPU fixture冒充原生执行。方法和评分身份改变才重测，不因文档更新重跑。

### TD01｜精确人口的标签与表示闭环：D1–D2，数据/学习负责人

以原12个TRAIN父episode为准，每父固定6个合法anchor，共72窗口。按各任务实际存在的关键事件选择；没有某事件不得伪造阶段，记录缺失。选择算法与实际anchor名单在看新模型预测前冻结；不足40未来合法命令的末尾窗口不跨reset补齐。

先复用同一R0/processor/codec/数据身份的已有真实测试。缺什么仅补什么：专家物理H40经同一参考门；专家动作经真实processor/逆变换的round-trip；核有效10维mask、相对SE(3)、rot6d约定、夹爪单位和0.05秒时钟。既有数值容限优先；确无容限时可预注册非裁剪fp32往返上限1e-5m、1e-4rad、1e-5夹爪单位，仅用于数值一致性，不是任务精度或安全门。精度/有损变换使其不适用时先给理论与dtype依据修订，不能看policy成绩后调容限。

交付`CONTRACT72.json`、专家与round-trip的逐窗差异/拒绝表。失败定位为LABEL、TIME、FRAME、PROCESSOR或CLIPPING；仅阻断依赖该错误的新训练，**不新增门阻挡原已合法E1/E2/旧Eval**。

### TD02｜可解释的学习读数：D2起，Vanda/学习负责人

在相同72窗口、两组固定实际noise上比较E0、E1@512、E2@512，最多432生成调用；E2未就绪先完成已有端点，不让E1等待。已有39份E0输出只在输入、权重、processor、noise完全相同时复用。新增查询须在相应有效范围内。

记录前1/8/40步位置误差、SO(3)角误差、夹爪事件/连续MAE、首点连续性、速度/路径原门、每窗实际梯度/参数变化已有证据及样本/事件曝光。对同任务关键分叉状态做语言配对；无正确反事实专家标签时只称条件响应，不计算“指令准确率”。优先自然合法的物体位置变化，不把黑图/乱序图结果当因果证明。

### TD03｜源域Teacher阳性对照：D2–D3，Core/数据负责人

### TD04｜接近—接触—抓放的16个有界小闭环：D3–D4，Core执行负责人

目标不是刷16/16，而是在D4前把主要瓶颈定位到动作/事件、条件化、参考安装消费或执行能力之一。一次安全停止不通过改阈值处理；同类失败最多一项冷态干预，不同时加平滑、改频率、改loss与换数据。

### TD05｜源域完整共享行为：D3–D5，Core执行负责人

先对旧真实失败、`tf_r3_teacher.py`/`tf_r3_worker.py`及实际目标manifest作版本差异表。明确哪些已具备持久参考/Prefix8，哪些动态消费/任务进度尚未证明；缺MPC消费标识写UNKNOWN，不把ACK等同求解完成。[S4][S5]

D4仍无实际合法接触/任务推进：标整机目标高风险；D5资格未成立：不盲采目标示范，不做目标学生完整盲测。源域线继续，最终按A未完成报告。此处不重启完整WBC研发，也不因旧hold RMS另加全局门。

### TD07｜一次失败机制选择与有界数据：D4–D6，审核负责人＋数据负责人

## 8. 科学纪律：小闭环不是小样本自我说服

原12父/6几何仍只有6个独立几何；7212重叠窗口不扩充独立样本数。TD02是拟合诊断，TD04中间状态是条件能力，TD05/09/10是开发，TD11才是冻结后的新人口确认。

复用旧DEV进行选择是允许的开发行为，但不能改名独立测试。新几何、相邻窗口、同一采集session、恢复后代和外观变体按谱系分区；对新TEST的任何可见开发使用都标曝光，另行报告而非隐藏。

E1/E2@512是参数范围对照；P-source/P-target是数据来源对照；CORR2048/R0的DEC1是旧预注册迁移实验。不得用TD10/11替换原DEC1父模型或拼成它的64格。无目标训练迁移成功与使用目标数据之后的适配成功分别报告。

源policy在目标执行器上生成的轨迹不必与源域逐bit相同，因为实际反馈已不同；需要相同的是权重和输入/动作语义。模型自身轨迹变化、参考安装变化、WBC实际偏差分别记录，不能靠离线时间平移把滞后消掉后宣称实时。

参考管理可处理几何/时间/可行性，但不能读目标真值替学生选择任务、在固定时间强制开爪，或忽略新命令伪装稳定保持。若任何接口会改变参考，必须同时保存原参考、安装参考和改变量，且只有明确版本的系统结果可计分。
