## 1. 当前结论与证据范围

**V1.9.6 支持继续以双冻结为主线。它证明了已抓持条件下的跨本体执行可行性，还没有证明冻结优于微调、可靠成功率或完整自主抓取。**

“冻结”指两端模型与控制器不变。GRA、BTF、时序和本体映射属于实际适配。准确名称是**无需新增训练的本体适配**；不能称整条系统未经适配直接成功。

## 3. 为什么先扩展这些任务

当前最接近成功的能力邻域是**持物后的运动与释放**。优先顺序为：

1. H：独立复现已抓持后的抬升与保持。
2. T：同一 GRA 下向目标搬运，完整保留模型开爪。
3. L：降低到桌面、由桌面支撑、主动释放。
4. G：固定系统下的空间、外观、目标和语言对照。
5. P/F：从无初始抓持开始，先近抓取，再完整起点。
6. C：单一整体指令连续完成多个阶段；最后扩展新的官方任务族。

H、T、L 各自可以独立推进，不把另一技能的成功或全局 4 mm 跟踪精度当作全部任务的前置。每个任务只依赖与自身相关的执行资格。

官方论文 Table 14 中 ARX X5 的 RoboDojo-Real 任务包括 `pack_and_pour_fruit`、`cover_blocks`、`store_in_safe`、`make_bread`、`make_food`、`insert_tubes`。因此水果的搬运／放置及覆盖方块的合法单臂子任务是有来源的候选；精密插入、复杂机构和多工具操作后置。论文任务清单不证明某个具体物体、prompt 或 episode 在该发布权重训练中出现。RoboCasa、RoboTwin 的另一个 checkpoint 的成功表不能移用于本权重。

正式 **LP00/LP10/LP01/LP11**：G00/G01 × seed 0/1。可在任一布局资格后立即执行，不等待全部 T 成功。

本次新任务的预登记判据：
- 首次持续释放边界已有原允许支持面的真实承托接触；物体最低点相对支持平面的有符号间隙绝对值不超过 3 mm，且原接触安全全部成立；竖直速度绝对值不超过 20 mm/s。评分容差不改变原安全门。

为避免把噪声变化误当成空间／视觉效应，另登记 **GB11/GB12/GB21/GB22** 四张 G00 名义场景 H，对应同一冻结 profile 和相同 seed。它们与 SPACE/VISUAL 配对比较；新 reset 的输入字节通常不同，完整记录差异，不能称严格同输入反事实。GOAL 的两方向本身使用相同 seed，LANGUAGE 使用交叉颜色／指令设计。

G-SPACE 需要新 H0 抓持初态；G-GOAL 需要对应方向的已知运动资格。最多预留 **QGS−/QGS+/QGG−/QGG+** 四张 0 模型资格，已有完全覆盖证据可复用。新布局在看模型输出前封存；若预定位置原生不合法，记该条件未资格，不在同一评价中随意缩小偏移到成功。G 面板合计 16 变化条件＋4 匹配基线＋最多4资格，共24卡。

G-VISUAL 所有图像来自真实场景渲染，三路图与历史同版本；不后期编辑策略图像。不会为了当前这一组重新搜索相机位置。

G-LANGUAGE 四条件必须全部按名册执行，不能只挑方向正确的输出。若离线检查使用完全相同观测／噪声，要报告输入字节相等；新 reset 的原生条件通常只能作匹配设计，不能宣称字节级同输入。

任何 profile 调整使用开发条件；本面板开始后不按成绩中途改配置。安全或技术阻断导致未完成时，报告完整登记人口与覆盖。

## 9. P/F：恢复自主抓取，避免把 GRA 当闭爪策略

已抓持的 GRA 不能直接套用到开爪端点。教师提供的抓持命令与预紧工作点属于 H/T/L 的初始化贡献，不能拿来替代模型在 P/F 中建立抓持。

### 9.1 先审计一个有证据的假设

复用已缓存的源数据与既有负例，核对：
- 源 action／state 的 achieved 与 command 语义，按实际 episode 验证，不把两个片段外推成全部数据。
- 官方任务 prompt、视觉槽位、当前／历史排列、颜色与实际物体一致性。
- 实测夹爪状态输入、自由开合输出、目标 TCP 与源 link6 的合同。
- 真实紧凑教师的抓前交接是否包含合理视觉和历史；不混入通用教师。

最多 24 次新冻结前向的诊断容量：8 个固定源正对照（4 真实锚点 × 2 噪声），以及 16 个目标对照（4 真实抓前锚点 × 2 噪声 × 原接口／一个有证据候选）。精确旧输入和噪声已有输出时复用并核哈希。不得借此展开无上限 prompt／相机／开度搜索。

仅有历史阈值 0.55 命中不代表能抓持；阈值未命中也不能被定义为全部原生 P 的禁入门。依据是新机制与原接口资格：有已证实的实现错误可修复后试 P；若完整预测持续明确张开且没有新假设，则保留 P/F 未启动，继续已有技能扩展。

### 9.2 无初始抓持的执行合同

P 使用真实开爪、无物体抓持、无教师物体搬运的近抓取交接；模型自己产生闭合、形成抓持、抬升。F 从原完整稳定入口开始，没有教师任务前缀。

若自由开合到接触保持需要新的通用夹爪控制律，另立 GRA-2 开发 profile，先以 **QP00/QP10** 验证自由开合、实际接触保持和正常释放。传感器只能使用已允许的本体反馈；没有真实可用传感器时不得把仿真物体 ID／目标姿态伪装成本体反馈。不得自主决定“现在抓取”，不得屏蔽真实释放。它不能与 GRA-1 的成功或 R0 的分母合并。

P 四卡 **PG00/PG10/PG01/PG11**：两布局 × seed 0/1。P 获得至少一个实际新增抓持与抬升正例后，立即固定 profile，并启动 F 四卡 **FG00/FG10/FG01/FG11**。F 判据为模型自主抓持、相对原 reset 抬升至少 20 mm、连续保持 1 s、闭环与原安全成立。

阶段终点分别是“近抓取自主形成抓持”和“完整起点自主抓取”，不能与 H 的教师初始抓持混称。

## 10. 后继确认、连续任务与新任务族

### 10.1 固定多技能确认：12 卡

H/T/L 三个技能分别在 G00/G01 × seed 51/52 运行，共 12 张。前提是每个技能已有资格与正例，并已冻结一份共同链接层配置。某项未达到前提，则其四张记未启动，报告剩余面板，不能改成三个 H 来凑多技能。

每技能达到 3/4 且两布局均有成功，作为本轮工程扩展标记；它不是总体成功率下界或部署保证。报告分技能、分布局比例及失败首因；若附小样本区间，明确抽样／独立性假设，不把固定布局面板当成任意任务总体的随机样本。调过 profile 后需要新的确认人口，不能重复使用该集合择优。

### 10.2 单指令连续任务：4 卡

固定整体指令：
`Lift the green fruit, move it toward the blue mark, then place it on the table at the blue mark and release it.`

H、T_MARK、L 各有实际正例且共同 profile 已冻结后，可从真实已抓持状态进行 **CH00/CH10/CH01/CH11**，以检验同一回合内策略自主完成抬升、搬运、受控放置。蓝标记事前候选为 G00 相对名义水果 reset 的 +Y 60 mm、G01 的 +X 60 mm；逐布局封存场景 hash 及方向、下降、支撑与释放路径资格。已有 QT/QL/QGG 覆盖可复用，否则运行 **QCH00/QCH10**，各0模型。G01不能继承G00的资格，候选不合法则该条件保持未启动。

CH 的 H 高度以初始交接为基线；H 的同时达标窗结束后，评分器记录实际物体 XY 作为 T 新增水平进展基线。T 达标后再评价 L，最终落点距蓝标记中心不超过20 mm。阶段按顺序、非重叠地评分锁存；抓持在 H/T 中保持，L 的合法释放不受独立 H 全回合保握条件约束。这里只改变评分器状态，不切 prompt、GRA 或动作控制。

全程不 reset 场景／模型历史，不由外部真值切换分段 prompt，不在阶段间用教师接管。各里程碑用于评分，不驱动动作。在完整 F 取得成功后，另行登记从未抓持 reset 开始的同一任务；**CH 的成功仍有初始抓持条件**。

本版本的 CH 每卡仍有 50,000 tick 有限终点。若原安全工作时长不足，在报告中注明未达长程资格；不得自动延长旧回合或重置脚参考。完整长程的更长端点必须在新有限作业中预先登记且不越过原安全。

### 10.3 新官方任务族：最多 8 卡的开发面板

首选从 `pack_and_pour_fruit` 的合法单臂子技能延展；第二候选为 `cover_blocks` 的单臂移动／放置子任务。先核对官方任务定义、实际目标资产、手臂角色、原接触规则与全路径可行性；不因名字就假定单臂可以完成双臂原任务。

启动前按来源／资产／接触可行性选定一个候选任务族，预留两布局 × 四 seed（61–64），共 8 张；每布局最多一张新资格卡。选择不依据试跑得分。确切 prompt、物体、成功谓词与资产 hash 必须在该面板首次前向前封存，此时由执行者按证据自主完成登记，不需要再次请求普通工程批准。当前标为 **DESIGN_ONLY_NOT_RUN**，不能冒充已经可执行的已资格任务；若只实现单臂子任务，不宣称原官方完整任务通过。

若新任务需要原 receiver 禁止的接触，记录 `BLOCKED_BY_CONTACT_SCOPE`，不扩大接触白名单来称“原安全门不变”。插接、机构、倒水和实机不进入近期主线。

## 11. 失败分流：一次失败要缩小一个问题

| 观测 | 下一步 | 不做什么 |
| --- | --- | --- |
| H 独立复现成功 | 固定 R0，扩 T/L 和预留条件 | 立刻同时改相机、夹爪、时序 |
| GRA 版 T 在正确消费后仍主动张开 | 保留策略行为；用 L 和目标／语言面板检验行为边界 | 加保握锁、裁掉张开后缀 |
| 静态持物也在同量级物理时间足漂 | 报告执行时间范围；审计前缀／冗余开销 | 把 GPU 墙钟当物理原因、重置足参考 |
| 只有特定轨迹足漂 | 检查负载、工作区、实际跟踪；必要时 RT1 对照 | 调 WBC 或扩大 5 mm 门 |
| 夹爪映射保持但物体滑移 | 对齐双指力、腕姿、相对物体运动 | 仅凭相关性宣布唯一 MuJoCo 根因 |
| 新视觉条件失败而几何条件通过 | 局部观测检查，单因素候选 | 全项目重新做标定 |
| P/F 始终没有形成闭合意图 | 有界源／目标合同诊断，报告边界 | 把张开动作硬映射成抓取 |
| 同一症状无新证据重复 | 切到归档诊断或独立任务路线 | 循环启动或永久停止全部项目 |

第一终止原因与机制标签分开，详见 RUNBOOK。模型因原足漂门提前终止的回合是系统任务失败；其尚未执行的能力是未观测，不能由此认定模型永远不能完成。

## 12. 工作窗口、容量与自主推进

以执行端实际 T0 为起点，Asia/Singapore：

| 相对窗口 | 优先交付 |
| --- | --- |
| 0–30 min | E0 绑定 R0；读回成功与首次失败链 |
| 30–150 min | HC 与同布局 QT/TG 交错推进，尽早得到 GRA 版 T |
| 150–270 min | 完成确认；足漂仍主导则 DS；可并行准备 L 资格 |
| 270–390 min | L 实际闭环；或有证据的 RT1，避免同时换多个因素 |
| 390–480 min | 完整当前小面板、冻结首个多技能 profile、全量结果与终态 |
| 后续工作窗口 | G 面板 → P/F 新机制与原生卡 → 12 卡确认／单指令 CH → 新任务族 |

时间是调度建议，不承诺到点成功，不为了赶时间删失败、截取成功片段或修改任务门槛。8 小时内不要求展开整条长程路线。

机读登记展开的全部条件容量为 **86 张原生卡，其中最多 68 张模型任务卡、18 张 0 模型资格／诊断卡；4,300,000 tick；8,184 次新前向上限（含最多 24 次离线诊断）**。这是所有有条件后继都启用时的规划总量，不是今晚应消耗的数量，不是申请新批准的门。前提不成立的条件保持未启动。

每张卡：最多 50,000 个 2 ms tick（含初始化／教师前缀）、120 次新模型查询（0 模型卡为 0）、1,800 s 墙钟；原门可更早终止。所有实际成本和技术中止保留。新的有证据后继可自主登记有限端点，不能修改已运行胶囊。
