## 1. 当前决定

**主线采用冻结 MAIN3.8K＋本轮实际 L1，先完成原 HOLD，再推进完整 PLACE；官方冻结 SLA-PT 并行做归因。** MAIN 已有抓持、抬升、保持的新增阳性，最短路径是定位它在完整任务前的剩余失败。PT 在多次真实消费后仍未接触水果，需要先区分意图、表示、源相位与实际执行。

具体安排：

1. 读回新回执及实际 L1 源码，解释每张 A 卡为什么没有完整成功；优先复用归档，不重新加载五个模型做大网格。

4. 固定一个候选，结算红／蓝原 HOLD 各两个新噪声条件。首张成功不提前结束面板。
5. 完整已知路径合格的 PLACE 布局立即进入后继；不把 HOLD 必须 4/4 设为新的硬前置。
6. PT 先分析全部 38 份返回和消费相位；明确执行错误先修，明确意图不足再进入独立命名的目标适配试验。

8. 首个成功系统封存后，做未参与调参的新布局小样本确认。开发成功、复现、泛化分开报告。

### 2.2 物体事件、原完整任务与闭环资格分别评分

- **阶段事件：**正确自主抓持、抓后 fresh query 消费、连续抬升≥20 mm 且保持≥1 s。抓持依原接触／物体判据，不以夹爪码替代。
- **原完整 HOLD：**从正常未抓持初态开始，满足绑定的原 HOLD evaluator 全部谓词、持续窗、终点与安全退出。既有阶段阳性后又 unsafe STOP，不自动算完整成功。
- **原完整 PLACE：**正常未抓持入口，单次初始任务指令，由模型完成抓、提、搬、释放、目标承托和撤离；达到原完整判据。教师只用于独立资格。
- **闭环：**至少两份返回有正量消费，至少一份来自自身运动后新观测；另单列是否有抓后 fresh query 正量消费。首次开环偶然成功保留物体分数，但不标闭环。
- **首次成功与确认：**已知开发条件的一次成功是可行性证据；四卡开发、六卡新布局确认分别报告。即使 6/6 也不是可靠性保证或对旧接口的独立因果验证。

先查明两张 HOLD 和四张 PLACE 各自的完整分数。若评分实现有 bug，只修实现，保留旧 scorer 的旧分数；对同一归档以新 scorer 重评分，old/new 并列，不能事后降低成功标准或缩短观察期。

### 5.1 MAIN 第一对诊断如何选

先选择实际归档里最有判别力的一个 HOLD 失败与 A06；若没有可判别的 HOLD 机制，第二对不自动启动。只以归档证据选择，ID 与唯一改动在新前向前封存。

可利用保存状态进行机械反事实，但必须具备相应模拟器、接触、控制器／MPC 缓存和消费边界的可恢复性；缺少隐状态时标明 matched reset。缓存预测回放只说明执行机制，不说明闭环策略能力；随后用真实新观测进行 M_HOLD 验证。

### 5.2 第一份完整 PLACE

从原四个 PLACE 开发条件或另有来源的开发清单中，在新输出前登记最多两个目标布局。优先已有长保持且完整路径可验证的条件，但明确这是开发选择。旧六卡完整 0/6 保留。

完整已知路径资格是实质前置；教师资格可与 HOLD 开发交错安排。M_HOLD 不满 4/4 仍可研究 PLACE，只要候选没有未修的共享实现缺陷、对应布局完整物理路径已过。不能把 Pick & Hold 教师阳性或持物中途初始化充当完整 PLACE 资格。

### 5.3 时间安排

按事件而非硬日期推进：第一工作块完成原件审计和阻断修复；第二工作块完成必要资格与 MAIN 的最小机制／HOLD 面板；第三工作块并行收敛 PT 归因与完整 PLACE 资格，再推进已就绪候选。首个工作块通常比扩大模型网格更有信息价值，但不承诺固定小时内成功。没有现场访问或正在运行的作业被接管时，发布计划不等于远端任务自动开始。

### 5.4 确认候选与任务的选择

在干净的开发面板边界，只从已完整结算、至少一次原完整任务成功且没有未修共享实现缺陷的系统中选择。先选已有完整 PLACE 阳性的任务；若没有，则选已有完整 HOLD 阳性的任务。同一任务内按 MAIN → 官方冻结 PT → 独立适配分支的固定优先级选就绪候选；不同任务族并存时沿同一固定路线优先级决定本批任务族。这是工程推进优先级，不按不同人口的成功率评优，不等待尚未就绪的其它模型。

任务族确定后，在最终候选封存前固定三个未调参布局的输入清单与重叠审计；候选、任务、scorer 和布局全部封存后才开始 Q_CONFIRM。若本批选 PLACE，而某个 Nxx 完整路径资格失败，保留 BLOCKED，本批不降成 HOLD、不替换布局。后来确需 HOLD 确认时另立批次／profile，保留 PLACE 阻断，额外资格不计入本表 34 张。

## 6. PT 专项：先分辨为什么没有接近

### 6.1 合同核对范围

复用原已核验证据，只核改动和不可信处：

- 官方 checkpoint／配置、三路 current RGB＋九张 head history、`extra_frames_first=false`、mask 与左右臂路由；
- 当前／历史图的真实传感时间，episode 首帧与其余历史的顺序；不能靠 frame count 把目标 20 Hz 当源 30 Hz；
- 官方 H50 双臂序、wxyz/xyzw、同 query 锚定 delta，而非逐行积分；
- source flange zero、episode-fixed mount、实时 world/body、真实 flange→TCP／指垫变换；
- 状态开度与 command 码不同；源 gripper 未物理标定的部分继续标 nominal；
- H50 首末名义跨度 49/30 s；P10 为实际执行合同，不能把前十行直接称 P10；
- BTF/GRA 的实际版本、适用类型与单次应用边界；重复调度不能累加补偿，不根据模型名称隐式叠加。

当前 RGB 路径在 #515 已核实，不做无证据的颜色翻转。#507 图像包对结果有显著影响，但它同时包含多路当前图和历史，不能单独归为某个相机或视觉 backbone。[E5][E6][E7]

### 6.2 最少新增前向与原生对照

优先复用所有归档。只有编译路径／依赖变化或原证据不能复用时，增加最多 4 次固定真实源锚点前向核对；目标端只对最多两个具体输入／表示假说做配对离线前向，每个最多 2 锚点×2 噪声×2 水平＝8 次。首工作周期总新增离线前向容量为 20，实际发生逐项记账。

如果相位停滞证据成立，PT_DIAG 固定原 P10 与一个新 profile，各两个 seed。保留完整源曲线、原 TTL、安全和有限滞后；不通过陈旧观测长期闭环、删后缀或放宽足漂换成功。

如果主要问题是足漂，先看同 native 时间 HOLD 与同 SOURCE 相位运动结果。已有教师 Pick & Hold 能精确复用时不重跑；必要时只补匹配暴露／负载的已知参考。半速延后 STOP 不等于增加任务进度，原 #515 已有此类反例。[E5]

## 7. 后训练是有条件的解决方案

本轮新接口审计和冻结面板的训练更新固定为 0。以下是有证据后可单独启用的后继，不让训练吞掉表示错误，也不要求所有其它面板结束。

### 7.1 触发条件

同时满足：

1. 实际输入、输出、frame/tool/time 与查询合同已核实；PT 后继另需保留官方源阳性，MAIN 后继核对其原 codec、目标数据语义和既有目标域基线，两条路线互不阻塞；
2. 至少一条同版本、同任务阶段的已知物理路径通过；HOLD 适配无需等待完整 PLACE 示范；
3. 全量意图／消费审计显示明确行为缺口，主要转换或相位错误已排除；
4. 有语义正确、实际消费可证的目标 TRAIN 数据及独立开发条件。

如果 MAIN 的 raw 明确缺乏抓后抬升、正确搬运或释放，就在独立 MAIN 后继中补该阶段的真实命令监督；不只增大接缝惩罚。旧 A/B 曾出现接缝改善伴随及时合法闭合和向上运动退化，必须同时检查这些行为。[E2]

### 7.2 数据与参数

- 先审计已有合格数据的任务、布局和阶段覆盖；旧 #474 的 57 回合为红 HOLD 19、蓝 HOLD 20、红右 PLACE 18，没有蓝 PLACE／红左 PLACE，也不是当前近源水果的现成示范。[E9]
- 从 TRAIN 条件采集／补齐正常接近、闭合、抓后首 query、抬升、保持；PLACE 另补真实搬运、释放、承托和撤离。学生偏离恢复数据也从 TRAIN 条件产生，禁止把用于评选的 A/B/CONFIRM 直接回填训练并继续宣称独立测试。
- 标注为实际已消费 command，监督 mask 只覆盖可证明消费区间。源 future-achieved 与目标 command 分类型，不将未执行后缀或实测未来 TCP 冒充专家命令。
- PT 首试复用 #474 的 **10 个 action-expert LoRA 张量、22,118,400 个参数（0.655%）**。父 action、IO、视觉和语言冻结；此前仅有 CPU 实载与屏蔽／形状资格，真实梯度和学习效果没有完成。[E9]
- 若训练目标为目标 WBC command，新分支名为 `PT_GO2_COMMAND_ADAPT_V1`，输出声明为 `COMMAND_REFERENCE`；不能学完教师补偿命令后继续默认叠相同 BTF/GRA。
- MAIN 后继优先动作侧、冻结感知／语言，实际参数集合及 optimizer 从可用原 recipe 绑定；参数范围改变是新干预，不冒称原配方已资格。暂不同时改变图像、统计、查询合同和损失。

### 7.3 首个有限训练试验

先在 8–16 个真实 TRAIN 关键窗口做读器、mask、真实 loss/backward 和重载诊断；若做 optimizer 更新，单独计数并保留诊断分支。正式 pilot 不从这个诊断权重接着冒充零起点。

首个正式 pilot 在首更新前绑定数据版本、训练采样、LR／optimizer、可训练参数名、随机种子、归一化及 **250 次固定更新端点**，保存完整可重载状态。PT 从官方父＋zero-B 新 adapter 开始；MAIN 从指定 MAIN3.8K 端点开始，两者不能混记。

250 端点完成固定开发条件并报告所有结果；不按最好中间 checkpoint 选成功。若后续确需 500，另登记由 TRAIN 学习、数值健康和已识别行为缺口支持的后继方案，保留 250 结果；不能以“DEV 不好再多跑一点”自动扩训。实际 GPU／站点权限、容量和原单 owner 机制仍需成立，不产生逐小修人工批准。

### 7.4 根据学习结果选下一步

## 8. 自主推进、失败和版本纪律

普通应用依赖、编译兼容、序列化、路径别名、入口路由、生命周期及记录缺陷按项目 V7 授权自主修复：[E10]。每次只写清“缺陷→改动→预期观测→受影响验证→新版本”；无需每个操作向用户索取 GO。

- planner 缺依赖：定位实际 import 和锁定环境，在隔离的项目用户环境修复；先零积分构造，再必要原生资格。不得 sudo／改变共享基础设施。
- 编译器中断：复现精确异常，用原固定输入和噪声确认数值行为；若修复改变 dtype、采样步数、RNG、decoder 或时钟，改列新 profile。
- 原 B_TARGET 仅在原科学合同恢复且数值等价时接续未启动条件；否则分新版本。技术失败的重试是新 attempt，旧失败和成本不消失。
- 原模型或物理安全门触发是有效科学失败。计划容量、启用、全启动、有效、技术、未启动分别计数。
- 连续同症状而没有新证据时，停止重复启动，回到归档／假说；一个模型阻断不冻结其它就绪路线。共享 STOP／身份缺陷才暂停所有受影响路线。
- 不打断健康作业，不热补活动 capsule，不强推 Git，不清理用户 checkpoint，不改变真实硬件或被隔离任务的权限。
- 若证据提示需要改变 WBC／安全门／真实硬件范围，报告该能力边界；本路线继续采用冻结条件下的可行方案。

## 9. 交付标准

每个工作块交付现有报告结构中的四个信息：新增行为能力、完整分母、首失败及证据、下一决定。成功视频从同一 run 的完整状态／视角生成，不能只剪成功窗当终态证明。

本计划执行完成的标志：

1. 六对 A 与 PT 的全量返回有可追溯归因表；UNKNOWN 和反证诚实保留；
2. 至少一个 SLA 系统从正常起点完成原完整任务，并具备真实反馈消费；注明是 MAIN、官方 PT 还是适配 PT；
3. 原开发面板完整结算，成功系统代码／权重／codec／时钟／场景和 scorer 封存；
4. 新布局小样本确认按全部启用人口报告；若只完成 HOLD，完整 PLACE 仍明确未完成；
5. 执行端所有实际资源／作业终态和费用登记。不能用发布计划、接口通过或 PR 合并替代上述成果。
