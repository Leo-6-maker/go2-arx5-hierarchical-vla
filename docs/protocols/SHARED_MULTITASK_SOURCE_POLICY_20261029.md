# 共享操作策略：源域技能数据、动作侧后训练与恢复

2026-10-29，承接用户最新提供的完整技术路线。最终第一版是一份共享权重，以同一EEF10接口完成抓放、推物、无锁柜门打开和单书放入指定格。E1/E2继续回答接口适配范围问题；不能用其12条抓推示范或512更新端点解释四任务能力。多书整理的观察历史、进度与子目标模块是后续独立上层工作。

## 技术选择

- 同一固定原始GR00T-N1.7父模型、同一NEW_EMBODIMENT槽位、同一processor/统计版本。以E2类动作侧联合适配为工程起点，E1保留为对照；这是方法选择，不是已测得E2更好，也不是继承E2 checkpoint。
- 输入保持双RGB、实际EEF/夹爪与指令；内部复用已有relative EEF处理，输出H40，四步生成，执行Prefix8，再观察。WBC继续冻结；不增加BASE头，不训练关节策略，不按任务分槽位。
- 源域任务数据独立于目标WBC能否成功。算法Teacher可以读取铰链、书本、目标格和接触真值；部署policy和adapter不接收这些真值、Teacher阶段或完成答案。目标相机标定/渲染配置可以用于源域视觉相容性准备。
- 先使用原生masked flow-matching；语言模型冻结，首轮视觉可冻结，保留由独立DEV诊断决定有限视觉适配的可能。没有新增几何loss或RL。

## 已实现的第一块技术代码

`scripts/pi0294/multitask/object_relations.py`：

1. 柜门转动从**当前实际**TCP、把手、铰链角度和有效抓握关系求解。固定工具—把手相对变换，沿铰链生成世界系EEF参考；正/反开门方向、非零初始开度和重新抓握偏移均显式参与。失去有效抓握时拒绝继续拉门。
2. 放书用实际工具—书变换计算目标EEF，而不是固定末端终点。目标书的八个角必须落入声明的书架空腔，预插入点从入口平面外侧生成。该矩形几何检查不能证明整段插入或接触可行。
3. 返回值均标记为`PRIVILEGED_SOURCE_GEOMETRY_UNEXECUTED`。这里只实现技能中的几何核心，**不是完整Teacher、成功示范或可直接训练的已提交动作标签**。完整接近、抓持、转动/插入、释放、撤离和恢复仍需源域接触物理执行。

`scripts/pi0294/multitask/sampling.py`与`reader.py`：

- 接入原有实际状态/已提交绝对EEF10/RGB读器，保留原relative processor和模型输入构造，不另造动作codec。
- 先均分四任务，再均匀选择episode，最后选择普通/关键事件窗口。每批32个窗口，每任务8个访问；普通与事件采样模式各半。普通模式也可能抽到事件窗口，所以这不意味着实际事件曝光率恰好50%。
- 恢复轮每任务6个原任务、2个恢复访问；两者内部仍各半普通/事件模式。事件按任务定义，不强行沿用旧五阶段表，也不把稳定张开等同释放转换。
- 恢复episode必须绑定策略实际访问的源域失败状态、精确恢复状态、学生模型与专家执行身份，且有从该实际状态重规划并物理验证恢复的记录。元数据声明由上游原件审计保证，本采样器本身不验证物理结果。旧Teacher同时间戳动作不是恢复标签。
- 统一新统计由初始四任务源域TRAIN拟合并冻结；恢复轮沿用该公共版本。新恢复分布是否受其覆盖需检查，不能偷偷更换某任务统计或clip。E1/E2原R0不变。
- DEV/TEST、目标WBC数据、未准入轨迹、空事件bank或缺任务bank均不能静默进入该优化人口。事件和特权元数据仅用于采样/旁路审计，不进入学生输入。

`recipe.py`给出可检查的**候选**数值参数：固定原始父版本`2fc962b973bccdd5d8ce4f67cc63b264d6886495`，AdamW，LR1e-4，WD1e-5，单GPU实际batch32（默认microbatch2×累计16），上限10000更新，warmup500，2000/5000/10000看独立DEV。它不启动Trainer；新参数成员审计、完整恢复保存、实际曝光与学习曲线仍需接入现有训练owner。恢复轮不允许直接误启动第二个10000步raw-parent配方，其优化起点/日程须另行具体定义。

## 数据与效果

首轮数据起点为50条抓放、50条推物、100条开门、100条单书的完整成功示范，允许先用嵌套小子集训练和开发。该数量是候选投入，不能据此预测成功率。训练开发可包含失败、修正和重复尝试，全部保留；独立测试失败不能删除。恢复起点优先取20–40个不同的实际源策略失败状态。

开门完整结果包括指定把手、实际开到预定义角度、释放撤离及保持；单书包括指令选物/选格、稳定放入、释放撤离及保持。阶段指标需注明全部尝试或条件分母。三本书连续整理不能用三次复位的单书成功代替。没有柜门或书架实测结果，因此不承诺80%或十天内成功。

## 当前实际与接续

最初的19项几何/采样/配方CPU检查保留。后继增加`contact_scene.py`、`source_engine.py`、`feedback_teacher.py`和`capture_core.py`，当前共37项CPU检查通过：

- 源场景只替换原固定底座源域方块和非接触目标标记，保留机器人XML、8个有限驱动执行器和物理选项。新门是被动铰链，书本是自由物体，书架提供真实碰撞/支持面；无新增物体执行器、mocap或工具焊接。完整源Engine继承原有限ARX5/夹爪驱动，显式共同home，新增实际铰链角度、书架支持接触和障碍碰撞反馈。此源Engine未在完整ARX5资产上运行，不是目标WBC的替代。
- 新反馈Teacher实现接近、对齐、抓持验证、转门或抬书/预插入/插入、释放、撤离与保持。正常H40仅每8观察产生，阶段内世界路径持续推进；时间走完不能换阶段。输送时失去真实抓持立即停止，后继恢复须从保存的实际状态重新建立Teacher。书本TCP抬高不替代实际书本抬起；插入需八角在格内（预声明接触容差1mm）、真实书架支持和实际速度满足条件。门目标角容差0.035rad、角速度≤0.05rad/s；保持需连续2秒实际满足，20Hz中间一次接触也重计。上述是新任务候选定义，独立最终评分尚未接入，Teacher完成标志不准入成功示范。
- 有限采集核心接已有owner的guard/持久记录回调，不新造调度或CLI。500Hz原驱动每25个实际tick对应一个20Hz动作区间；完整H40只作未执行参考旁证，每个真正完成25tick的前缀点另记提交/完成。中途安全停止、预算或记录失败不生成该区间的完成标签，更不能把未执行后32点放进训练。学生观测只含实际双RGB/EEF/夹爪和指令；特权接触/阶段留在旁路。
- 实际MuJoCo检查只编译了门、书两个**无机器人物体fixture**并运行`mj_forward`，没有调用`mj_step`；确认被动/自由DOF、真实几何、初始变换和四元数顺序。其余执行、失败和记录测试使用显式CPU fixture，不能当完整机器人运行证据。

新增源域物理rollout、成功示范、GR00T加载及训练均未执行。S1自有原件的本轮只读核验仍为资格lease CLOSED、输出仅原入口probe、匹配本run进程0；未重开lease或推进物理。这些检查不能写成技能成功。

接续实现需将这些源组件接到原统一入口/owner，完成完整ARX5资产、共同home、碰撞和双相机原生资格，补独立最终任务评分与冻结导出，再提出可审查的有限source pilot资源；当前库不提供该新范围的启动权限。随后先测完整任务和恢复，再冻结小包接原Trainer。模型上线后从其实际访问状态补恢复监督。整机S1已批准的四次抓推开发仍独立推进，用于冻结WBC承接能力；它不是源域新技能数据的前置准入门。

本方向更新优先于旧路线中“只做最少参数12条抓推/柜门先测后采、暂不放书”的方法选择，但不改写已固定E1/E2、D25/GEN1和DEC1对照。原费用、资源保护、截止、现役任务非抢占及历史失败保留。300条示范、10000更新和恢复实验是待核算的新范围；PR144十天候选资源和S1有限批准均未自动授权这些开支或延期。下一次资源决定应针对已完成可审查的源域pilot实现和完整剩余预测，不能挪用S1额度。
