# PI0294 Frozen CPU Qualification Recovery

This repairs CPU-stage recovery only; it does not authorize neural execution,
a fifth PBS allocation, new data collection or a deadline extension.

The original CPU qualifier builds a bank and then checks the official codec
over every window. A later retry cannot call that export again: the first
bank freeze is immutable and TRAIN statistics must be fitted once.

`scripts.pi0294.cpu_pipeline` now accepts `--qualification-attempt 2` with
`--frozen-bank-seal-sha256 <exact-original-seal>`. The registered CPU manifest
must bind the exact original dataset manifest and statistics hashes. The
implementation checks the original seal, full member set and every member
hash, the terminal/frozen bank flags, scene-plan version and fit count.
It never calls the exporter in this mode. Partial banks, changed members,
symlinks, altered statistics, missing seals and already successful first
qualifications are rejected.

The original failure and first output directory remain. Recovery uses a new
qualified evidence namespace, not replacement of the failed receipt. It
repeats the same complete official TRAIN/DEV tensors, all-window codec and
native 0/2/4-loader consumption/resume gates; no sampling reduction, new
threshold or DEV refit is introduced. An interrupted serial codec has no
durable partial proof, so its incomplete work is not counted as a pass.

Dispatch is conditional on actual first-attempt failure, verified terminal
original parent/child/process groups and reconciliation of the exact old
CPU reservation by the sole owner. No restart occurs merely because a read
timed out or SSH disconnected. The first stage's original deadline remains.
A distinct second-stage ticket may reserve at most 3600 wall seconds on the
same three CPU cores, always clamped to the original 09:00 SGT cutoff and
remaining 160-core-hour total. CPU and storage counters are not reset.
Existing frozen-bank bytes are not charged as newly generated bytes again.

The first running source, physical source, mutable canonical checkout,
Hopper source, M512 weights and v3.0 training statistics are unchanged.
Any recovery consumes a new pinned CPU-only capsule after the actual idle
boundary. Publication and mocked CPU fixtures do not establish actual
deployment or full data qualification.
