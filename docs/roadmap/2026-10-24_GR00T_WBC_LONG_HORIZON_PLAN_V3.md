## 1. 研究目标、系统身份与主张边界

### 1.1 核心问题

在高层训练不使用目标 WBC 产生的任务示范、不联合训练或调参目标 WBC 的约束下，同一份语言条件 EEF 策略能否跨独立源执行器与冻结目标 WBC 复用？实际执行进度反馈能否提高这种迁移下的完整物体任务成功率？

当前源域是固定基座 ARX5 独立 IK／PD 仿真，目标是 free-root Go2＋ARX5 冻结 MPC／WBC。两者借用部分相同机器人资产，并不执行同一低层策略。源、目标还可能同时改变身体运动、相机观测和动力学，首轮结论准确称为 **executor-domain transfer**。仅凭现有两域对照不能把差异全部归因于 WBC，也不能宣称任意机器人可替换。[现役执行器边界]

若 A/B 都不达开发门，不打开 LOCKBOX。先报告覆盖干预的实际结果，再依据第 8 节决定是否存在一个已获准或后继有界的学习干预。不能在同一 DEV 上不断训练直至碰巧过门。

### 5.3 训练随机性复核

沿原协议对胜出局部 recipe 做一次不同 seed 复核。这里复核的是该次增量训练，不是整个预训练及所有历史阶段都独立重复。若复核不能达到每任务 18/24，报告训练敏感性，不凭幸运 seed 打开主级验收。若因资源省略复核，最高只能为 BETA，不能称 PV1_VALIDATED。

新 scope 若希望主张“训练方法稳定优于对照”，需要额外匹配 baseline 和 intervention 的训练 seeds；该后继设计与本次单次复核分开。

### 5.4 只有一个冻结候选进入 LOCKBOX80

LOCKBOX80 是 20 个全新 scene group × 2 任务 × 2 噪声银行。冻结模型、processor、stats、runtime、precision、语言和动作 schema 后再打开结果。原级别保持：

| 标准 | PV1_VALIDATED | PV1_BETA |
|---|---:|---:|
| 每任务完整成功 | ≥32/40 | ≥28/40 |
| 每任务在两 bank 都成功的场景组 | ≥14/20 | ≥12/20 |
| 每个 task × 预分配 family 的完整成功率 | ≥50% | ≥50% |
| 每任务 S1 拒绝 | ≤4/40 | ≤8/40 |
| 实际 native 安全故障 | 0 | 0 |
| 审计、交付和完整分母 | 全部成立 | 全部成立 |

不达门则交 BEST_RESEARCH_CANDIDATE_NOT_QUALIFIED。已打开的最终集不能再给第二候选选优。工程缺失保留，替代次数沿原有限规则；合法失败不重新抽种子。[PV1 协议]

### 5.5 最小交付与成本

交付源域策略卡、三路完整 DEV 表、选择路径、seed 敏感性、最终 80 条件或未打开原因、全部失败和模型加载身份。按几何组报告 0／1／2 成功分布及成组区间，不能把两个 noise 当独立场景。

若原 130 条件全未补齐，上界为 10400 次 2.5 Hz 模型查询；每完整条件 16000 live ticks，若精确前缀 shadow 总量同级，则 live＋shadow 约 4160000 ticks。实际费用还需加入模型加载、初始化、失败、重建审计及关闭成本。该上界只用于预算核算，不授予新查询或物理额度。源基线已有结果不重复收费。

## 6. M2：完成固定旧 CORR 的首轮解耦科学结果

### 6.1 入门资格应直接对应真实执行

源和目标各自证明当前版本的：

- 实际观测、双相机、TCP／frame／rot6d／夹爪语义；
- 原始与映射完整 H40，以及实际执行 prefix 的合法性；

只引用当前任务必要的既有证据，不要求重新交付整个 WBC 包。零 tick 构建、渲染、CPU 测试、12 维 MPC 预测绑定和历史 Stage20S 都不能单独替代本轮动态任务资格。source 单 pose ABI 与 target 时间化参考 ABI 可以不同，上层语义和两臂比较保持一致。[现役执行器边界] [目标当前计数]

### 6.2 核心 64 格与唯一干预

固定旧 CORR@2048／R0；8 个新独立几何 × 2 任务 × 2 执行器 × 2 接口 × 1 个预定噪声银行。

I_TIME 使用正确名义时间；I_PROGRESS 仅使用实际 TCP／夹爪反馈决定局部有界、单调的轨迹进度，保留模型夹爪事件顺序。参数由 source TRAIN／无物体 CPU fixture 固定，不使用 target 确认结果搜超参。两臂共用正确的 frame／TCP／软件 bug 修复、推理精度、噪声序列、32 秒物理时限和安全规则。

同几何配对实际对象／目标初态；各执行器使用自己的真实机器人／相机观测，不伪造后续 RGB 一致。按 geometry block 交错执行，所有 valid fail 留存，禁止 best-of-N、延长到成功、Teacher 接管或任务 ID 分支脚本。新目标确认数据不回流任何训练／归一化／进度参数／预测器。[DEC1 协议]

### 6.3 分析与结果出口

主要效应是 target 上 PROGRESS−TIME 的成功率差；同时给 source 差值及两者 interaction。按 8 个几何 block 配对和成组重采样，不按 64 个独立样本计算显著性。逐任务、方向、拒绝机制、完整物体失败、实际进度延迟和原始计数同时报告。单一 inference noise bank 与单一训练结果限制随机性主张。

| 实际结果 | 允许结论 | 下一步 |
|---|---|---|
| 两任务 target 有完整成功，progress 有一致正向线索 | SUPPORTED_PILOT | 新几何独立确认，不能立即宣称通用优势 |
| target 成功，但未观察到明确 progress 增益 | 初步可复用；接口收益未观察到或仍不确定 | 按效应区间决定是否值得独立确认，保留简单接口作为选择 |
| source 与 target 都很弱 | SOURCE_POLICY_LIMITED | 保留本结果，优先解决源能力；小迁移差不是鲁棒性 |
| source 有能力、target 主要失败 | 具体执行域失效边界 | 从 raw／installed／actual／time／task 记录选一个假说，另立新版本验证 |
| target 仍不合格 | TARGET_EXECUTOR_BLOCKED | 交唯一差异缺件清单及未运行格，不计算虚构 transfer Δ |
| 工程／资源不足 | INCOMPLETE_RESOURCE_OR_SITE | 保留分母、费用和缺失，按原时钟收尾 |

首轮没有观察到增益或效应区间跨零，只能报告“未观察到额外收益／结论不确定”；只有区间已排除事前定义的最小有用增益，才支持“无实用增益”。低成功率是否值得扩大研究，应在完成当前预登记 pilot 后决定。

后继发现共用软件 bug 时，两接口共同修复、固定新版本并使用新确认 cohort；原结果不删除。不可把调 WBC 或改安全门当作接口实验的 routine fix。

### 6.4 可选 stress

原 DEC1 预声明的 target 100 ms 延迟 stress32，仅在核心完整、延迟 buffer 保持原安全语义、原生已采用剩余封套能覆盖全部成本时运行。无法覆盖则 NOT_RUN；不挪用最终保护，不把当前 88 episode 封套自动理解为包含全部 commissioning＋core64＋stress32。其几何已打开，应标为 stress，不称新盲测。

## 7. M3：独立确认与训练随机性的后继提案

状态：**PROPOSED_FUTURE_SCOPE**。只有 M1／M2 产生足够信息后，才确定模型、首要假设和预算，不能一开始同时开启大量 seeds、物体、语言、第三执行器。

### 7.1 确认人口

建议把独立几何扩到至少 20 组。一个可用于预算估算的例子是：

**24 新几何 × 2 任务 × 2 执行器 × 2 接口 × 2 inference noise = 384 条件／固定模型。**

384 是工作量示例，不是统计功效保证。正式数量应在看新结果前，根据最小有用效应、几何内配对不一致率、任务分层和可承受预算确定并封存。保留全部原 TRAIN、DEV、CONFIRM、LOCKBOX 及其几何兄弟的排重；确认几何不得按策略成功筛选。

两 inference noise 检验动作采样敏感性，不能替代独立训练 seed。若采用 A/B 新模型，必须单独注明新 cohort 和父模型，不替换已运行的旧 CORR 核心。

### 7.2 训练方法的复核

如要进一步证明覆盖或后继方法的收益，可提出 **3 个独立训练 seeds 的匹配 baseline／intervention**。若同一个历史 CORR 父模型保持，结论限定为该局部训练 recipe 的随机性。控制两臂父模型、更新、样本访问、任务比例、可训练参数和硬件数值语义。

正式 scope 须先固定“模型 × 评估 panel”清单。3 个 seed 的匹配两臂为每臂 3 次、共 6 次训练；若 6 个模型全部执行 384 条件，则为 2304 条件。是否全部进入完整迁移 panel 应在结果前确定，不能仅按 384 计总成本；本文不要求自动运行 2304 条件。

报告每 seed 的表现及跨 seed 差异；几何、任务、noise、训练 seed 具有层级相关性，不把所有 rollout 简单合并成更大的独立 n。若预算不足先完成一个清楚的确认问题，不能同时声称训练稳健性与接口普适性都已验证。

### 7.3 出门与停止

出门需要效应区间、逐任务一致性、实际成本和失败边界。区间跨零且仍包含有用增益时标记不确定；只有区间已排除事前最小有用增益，才支持无实用增益。不能不断增加样本直到结果显著。发生 native 安全错误立即停相关 lane；有效任务失败继续按冻结矩阵完成。

若已完成 pilot 的 source／target 成功都接近零，可以决定不启动扩大确认，先解决源能力；若 source 高、target 低，先定位单一域差异。已封存并开始的确认矩阵继续完成，除非触发原安全／工程停止条件，或事前已注册的有界 futility 规则。临时停样本须报告为 partial，不能充当完整确认。若接口增益很小而复杂度／延迟显著上升，应保留简化结论。

预算公式：N 条件 × 实测 end-to-end 分配秒／条件，加模型加载、有限工程 allowance 和关闭费用；单独计 N×最大查询、live／shadow ticks、构造数、存储和传输。384 条件不能直接装进原 88 条件封套。

## 8. M4：按证据选择一项学习改进

状态：现役 PV1 已登记的条件分支仍受原 scope；超出当前时钟、次数或资源则为 **PROPOSED_FUTURE_SCOPE**。每轮只改变一个主要科学因素；R1、数据扩展、事件采样、纠正数据、新网络和新 loss 不一次叠加。

### 8.1 R1：先区分表示改变与新增数据

R1 会改变归一化输出到物理动作的映射。完整实验需要匹配训练和推理统计，不能把旧 CORR 直接换 decoder 后当作同一策略的无成本改进。

建议按两步执行：

**R1-A：共同物理支持上的表示对照。** 从 R0 与 R1 都能忠实编码／解码的同一批物理示范开始；两臂同父、同更新、同任务曝光、相同可训练图谱和固定 seeds，分别采用匹配的 R0／R1 训练及推理解码。输出 encode/decode 误差、动作边界及完整闭环任务结果，检验表示变化是否有独立收益或退化。

**R1-B：固定 R1 的数据覆盖对照。** 在 R1 固定后，比较旧数据与旧＋CR2／D48 新数据，匹配访问总量、任务比例和其他设置。46/48 等 Teacher 结果只说明候选数据来源；学生收益由新闭环结果给出。

若某些新数据无法用 R0 忠实表示，不制造一个剪裁失真的 R0 臂再称“纯 normalizer 消融”。没有共同支持的 2×2 单元就明确缺失；两个顺序实验各自回答不同问题。原 R0 A/B 结果与统计完全保留。

### 8.2 路线 R：真正学生状态上的纠正监督

只有对应任务的 Recovery Oracle 在预登记 TRAIN 状态中达到原要求的 **至少 5/6 完整安全恢复**，才能生产该任务的正纠正标签。旧 T2 0/2 恢复不能充作资格。

学生先真实执行并形成偏离状态；专家从同一 actual state 提供后续参考。保存学生动作、被拒绝但零 live 的建议、专家提交动作、实际 ACK 和物理转移的不同身份。只安装通过原门的动作，只把真实完整成功的合格恢复作为成功监督；task/object 真值留在 Teacher／评分侧。

现役 PV1 分支上限为最多 24 个独立学生 episode 和最多 24 个恢复 fork，任务各最多 12，按原规则固定 task 内纠正访问比例。跨过旧截止后须新有界卡，不自动恢复这些历史额度。对照同父同更新、保留 replay 与原任务能力。

出门要求独立场景的完整任务收益、S1 拒绝减少和 T1／T2 保留。没有合格 Oracle 或收益只限旧 parent，就停止 DAgger 扩张，保留普通 BC 数据线。

### 8.3 路线 E：物理事件采样

只有独立 TRAIN 诊断同时显示真实事件级拟合问题与实际执行 Prefix8 的曝光不足，才改变任务内 anchor 采样。释放、脱离、withdraw、hold 等事件必须来自稳定物理定义；不能用旁观 Teacher 标签或高频接触抖动充当独立事件。

事前冻结概率表、parent 权重和总访问量。对照不同时加入新数据、新 loss、R1 或新网络。报告各事件的实际消费、整任务成功与未改进阶段。仅 H40 平均 loss 改善不够；如果完整成功及保留没有改善，结束该干预。

### 8.4 选择原则与预算

先看完整失败证据：表示裁剪对应 R1；学生分布偏离且 Oracle 合格对应 R；物理事件拟合与曝光共同不足对应 E。证据不足就不再训练一对新模型。

预算分别列两臂更新 × 实测更新秒、完整 checkpoint 峰值、采集／恢复的实际和 shadow 物理、同一开发与新确认人口。采用完整成对比较所需资源不足时，不启动只可能留下半个对照的新干预。

## 9. M5：机制消融和任务泛化

状态：**PROPOSED_FUTURE_SCOPE**，一次优先选择一个问题。所有比较仍保持 WBC 冻结、正确共用软件基线和原任务评分。

### 9.1 进度机制

在主比较完整后，检验实际反馈进度是否优于一个简单、合法的延迟补偿时间基线。给两者相同实际反馈可见性、模型调用次数、任务时限和安全规则，避免把更多信息或更长时间记为算法优势。

明确静止、纯旋转、重复 waypoint、原地夹爪事件和新 chunk reset 的机制；测试参数由 TRAIN／无物体 fixture 冻结。失败若来自共同 frame／TCP 错误先共同修复，不能故意保留有缺陷的 baseline。

### 9.2 语言条件和分布泛化

同一物理初态分别执行 T1／T2，检查语言是否改变抓取／不抬升推送等过程约束。未来未见同义表达使用事前冻结的指令表，不根据结果选择“模型听得懂”的句子。

布局、视觉外观、语言与物体实例尽量分开改变；每个维度用独立新确认组。物体外观或布局泛化不等于新任务泛化，两任务不会自动成为开放词汇操纵。当前冻结 plant 条件下不擅自加入地形、摩擦、惯量和腿策略变化。

### 9.3 纯控制器归因与第三执行器

只有存在同 plant、同相机和同其他条件下的两个真实独立冻结控制器，才提出纯 controller causal 对照。改 source gain、焊死 target 基座或给同一个执行器换两个函数名都不成立。若无法控制这些因素，继续使用 executor-domain 的准确主张。

第三执行器需要实际参考、观测、task、safety、ACK／STOP 和工作域资格。它是后继泛化证据，不是完成两域主实验的前置，也不能从接口 schema 相同推断已兼容。

### 9.4 实时性

独立记录模型服务、跨机通信、安装、物理推进、总 wall-time 和各环节尾延迟。0.4 秒仿真前缀不是 0.4 秒 wall-time 保证。先确认实时需求与可用计算，再提出有界异步／延迟处理方案；任何改变因果顺序、观测新鲜度或安全时序的优化都需单独资格。

出门以真实端到端延迟分布、丢帧／超时、任务保持和安全证据为准。CPU 测试、平均模型 forward 时间或更少日志不能单独证明实时部署。

## 10. M6-A：动作条件后果模型、规划与蒸馏

状态：**PROPOSED_FUTURE_SCOPE**。它延续既有长期策略，当前不会替代 GR00T 主线，也不成为数据、A/B 或冻结 WBC 迁移的前置。[既有世界模型策略]

### 10.1 先证明存在值得学习的动作选择问题

只拥有成功专家轨迹，可能不足以识别“同一状态换一个动作会怎样”。先在新授权的 TRAIN-only 有界试验中，封存代表性独立状态组、少量候选与真实执行／合格 shadow 身份，检查候选集合是否存在有意义的改进空间。

可用于预算的例子是 **12–24 个独立场景／状态组 × 每组 4 个固定候选**。这是 PROPOSED 规模，不能直接运行；正式状态、候选、停止、物理与查询上限需新卡冻结。若候选普遍无用，应改善行为先验或恢复数据；若存在好候选但单次策略选不中，再研究后果预测与排序。

### 10.2 数据准入和合法输入

输入来自部署可见历史、图像、语言、实际 EEF／夹爪状态、历史已执行动作，以及本次待评估的候选 reference／action chunk、其时间语义和明确执行器身份。候选动作作为预测条件；未执行候选及未执行 tail 不能被记为已有实际转移监督。物体／接触真值可作 TRAIN 监督与独立评分，但不能未经披露进入在线模型输入。

| 数据类别 | 正行为监督 | 后果模型可用性 |
|---|---|---|
| 合格成功 TRAIN 示范 | 可用 | 真实执行转移可用 |
| 合格但任务失败的 TRAIN rollout | 不能直接当成功动作 | 实际转移和失败后果有价值 |
| 学生偏离＋合格专家恢复 | 仅合格专家提交参考 | 学生／专家各自实际转移分开使用 |
| S1 拒绝且零 live | 不可作成功标签 | 有拒绝标签，无已观察碰撞转移 |
| 合格 shadow 反事实 | 不自动等于真实专家 | 标明 simulator、父状态、parity 和误差 |
| DEV／CONFIRM／LOCKBOX 及其分支 | 不可训练 | 预测器、规划器和蒸馏也不得训练或校准 |

先按场景、物体和学生 parent 划 split，再切窗。不得用“只训练世界模型”绕过测试隔离，也不能删除有价值的失败 TRAIN 转移来制造全成功数据。

### 10.3 最小预测模型与验收

先预测一个真实执行前缀约 0.4 秒的物体运动／EEF 响应／抓持释放事件及不确定性；仅在结果支持后扩展短多步。冻结视觉表征加小型动作条件模型可作为起点，模型尺寸本身不是贡献。

必须包含静态保持／简单运动、无动作输入、错误或打乱动作、直接结果评价器等基线。检验同状态候选排序、位移／抬升／释放／目标误差、校准与分布外不确定性。全预测“安全”带来的高 accuracy 不能验收稀有风险。

正式协议在新结果前固定最小有用排序改善和可接受计算成本；报告单步／短多步误差、概率评分、选择遗憾和覆盖—风险关系。若模型忽略动作、比简单基线无用或误差随短 rollout 迅速累积，停止规划分支。

### 10.4 等候选、等成本的规划对照

只有动作敏感性及有用排序成立，才比较：

- 单次 VLA＋原安全门；
- 同 K 个 VLA 候选＋固定随机／简单几何选择＋原门；
- 同 K 候选＋学习的直接结果评价器；
- 同 K 候选＋动作条件短程预测／规划；
- 有限合格仿真 oracle，仅作为诊断上限。

各选择器共用候选身份、初态、训练数据边界、同一安全筛选和最大实际计算／延迟预算。报告 K、模型调用、GPU／CPU／shadow 费用及放弃次数。不能把 K=4 的系统仅与 K=1 比较后，把多次生成的收益全部归给世界模型。当前禁止 best-of-N 的 PV1／DEC1 仍不改变；后继 planner-assisted 系统具有独立身份和独立确认集。

若超出预测支持、置信不足或原安全门拒绝，走事前固定的原策略／停止出口，不通过更长搜索利用模型漏洞。主要结果仍是完整物体任务成功和过程约束。

### 10.5 蒸馏出口

规划器先在 TRAIN-only 实际或合格模拟中证明收益，再把经验证参考用于蒸馏。想象成功、低不确定性或高评分本身不能当作专家标签。继续 BC 与加入恢复／规划监督的两臂同父、同更新、同任务曝光，独立报告 parent 数与重叠窗口。

分别交付单次 VLA、planner-assisted 系统、蒸馏后单次 VLA。只有蒸馏保持任务收益并降低实际在线成本，才考虑扩大。若必须保留在线规划才能有效，应披露该代价，不把整个系统包装成无额外组件的旧 GR00T。

## 11. M6-B：真实 EEF13／BASE、目标少样本与硬件边界

本节与 M6-A 为后继备选，不能默认同时启动。均为 **PROPOSED_FUTURE_SCOPE**。

### 11.1 非零 BASE 意图

目标端 EEF13 接入与评价以目标 EEF10 原生链有效为前提。独立源域的 BASE 数据与训练需要合法可移动源执行器、真实非零 BASE 监督和匹配观测，不以目标任务成功为前门；当前固定基座 source 本身不能提供这样的移动数据。记录 desired／installed／actual BASE 和 EEF、时钟、夹爪、控制器身份；ABSENT 与 ZERO 分开。

建立新数据版本、模型头／mask、normalizer 和独立 split。先选择声明工作域内的近／远任务，评估物体成功、移动协调、稳定性、停止和实际成本；继续冻结底层 WBC。没有真实非零数据就标 NOT_RUN，不给 EEF10 补三零作移动学习。

比较应明确新增 BASE 输出带来的信息、数据和训练差异，不能仅因模型动作维数从 10 变成 13 就声称已学整机协调。相机／frame 随基座运动的变化需实测并公开。

### 11.2 少样本目标适配

旧长程路线中的 source-only／每任务 5／20 条 target 示范，可保留为后继数据效率研究。每条 target 成功示范必须在真实冻结目标执行器上完成并通过数据审计，独立场景数不能用切窗替代；目标 TRAIN、DEV、确认人口隔离。

同源父模型、固定增量更新和匹配数据／动作语义比较，披露真实目标示范数量及目标端感知／接口校准。使用目标任务数据训练的策略属于 target-adapted 模型，不能再计入当前“零目标任务示范”的训练主张。未达到 5／20 独立示范档位就报告缺失，不重复同 episode 凑数。

### 11.3 真机

本计划没有真机执行授权。仿真任务成功、零 native fault、接口兼容或已学 BASE 均不自动构成硬件准入。只有另行确定硬件、现场责任、真实通信／停止、工作域和有界任务协议后，才讨论真机验证。当前结果包默认不触发真机运行。

## 12. 预算、吞吐和可靠性：以完成实验为单位

### 12.1 每个后继 scope 都列完整成本

预算至少包含：

- 训练：两臂及 seeds 的实际优化器更新；重试和丢失更新照计，不只记录最终 checkpoint。
- 推理：模型加载、兼容 probe、有效任务、失败与替代的全部查询。
- GPU：实际 allocated time，包括排队后分配但模型未加载的 pre-CUDA 消耗；不等同模型 CUDA 利用率。
- CPU／物理：实际 core-seconds、live／shadow／重建 ticks、engine／clone 数、episode starts。
- 数据：峰值驻留、暂存与完整 checkpoint 同时存在的生命周期峰值、传输、恢复和归档。
- 控制与收尾：owner、心跳、有限诊断、结算和停止成本；保留最终完整评估的保护额度。

可复用公式：计划 GPU 分配 = 训练完整封套＋评估驻留封套＋有界工程余量＋最终验收保护。训练封套用实测 step 成本与 checkpoint 时间；评估封套用 end-to-end condition 时间和加载／通信／物理成本。H200 与 A40 的秒数不能直接互换为保证值。

### 12.2 先核完整对照，再启动新模型

每次候选启动前检查：余量能否覆盖本候选训练、匹配对照、固定开发人口、必要 seed 复核、唯一最终验收和关账。不能以“训练已花很多”侵占保护额度，也不能删掉困难条件减少分母。

当前 PBS17／28 是上限的准确调整，不是还有 28 次新提交；增量回执下实际已用 25／14，只剩原三份 matrix 的提交位置，B1481574 已经计入。原始已用、已预留与当前可用分别展示，原 pre-CUDA 费用不退款，原已关闭 lease 不重开。未来 source130、确认384、训练3seeds和 planner 候选都单独计算，不互相暗含。[唯一提交增量]

### 12.3 性能优化的验收

优先复用现有控制面、loader、IO 和恢复修复；只解决有实际证据的瓶颈。性能指标以 **已审计有效条件／allocated GPUh、可恢复更新／实际更新、完整比较的 wall-time** 为主。CPU 测试数量和文档数量只反映准备程度。

任何 worker、微批、缓存、数值归约或 trace 改动，在冷态新 capsule 中验证同样本游标、RNG、梯度／恢复语义和实际吞吐。不能热改正在比较的一臂，不能把未验证 CPU 一致性写成 CUDA 提速。若优化收益不显著或增加不稳定性，保留旧路径，优先完成科学比较。

## 13. 单 owner 执行、数据治理与日常报告

### 13.1 执行归属

当前采用单 logical native owner 和 Vanda-only 方向。一个共享 checkout 一个 mutation publisher；服务器运行固定 source capsule。资料／代码 helper 不取得远端 mutation owner，不新增平行调度、抢卡或多份 qsub。合法已批准的普通同范围工程修复无需重复索权，真正资源不足或新科学 scope 单列准确差额。

发布 GitHub 管理代码与文档、现场采用、真实作业开始、模型更新、物理结果分别报告。每个关键动作给对应不可变身份，不以管理 HEAD 当作正在运行的源版本。[仓库交接规则]

### 13.2 数据与模型生命周期

保护旧父模型、固定对照、当前完整恢复＋必要回滚、已用于选择的终点、最终候选和唯一失败／安全证据。数据分割贯穿 BC、DAgger、normalizer、进度参数、价值头、世界模型、planner 和蒸馏；任何一个模块看到正式测试都构成泄漏。

只有原维护权限内、无 active consumer／恢复／科学引用的大 payload 或可重建 cache 才可按既定退役程序处理。没有合格对象就如实 0 删除，不因训练失败而丢失有价值的负面转移。不把 raw RGB、视频、checkpoint、凭据、vendor WBC 或 host-bound 私有路径写入 Git。

### 13.3 最小进度入口

复用 START_HERE、当前状态和 #11／#47 的既有分工，不创建另一套账本。最新摘要只需要：

1. 当前最强已完成行为结果及其统计人口；
2. 作业实际状态与最后完整恢复点；
3. 目标 native 资格、核心矩阵完成／有效失败／工程缺失／未运行数；
4. 已用、预留、最终保护和下一固定截止；
5. 下一项能改变决策的动作及唯一阻断。

活跃期沿原频率报告真实里程碑。长报告保留证据，入口摘要保持短；旧“Latest”段落加日期和历史身份，避免读者把过去的 R/Q 当成当前状态。

## 14. 风险、预警与失败出口

| 风险 | 可观察的预警 | 动作与出口 |
|---|---|---|
| token／heartbeat 再次中断 | 认证寿命不足、owner heartbeat 不连续 | 提交前冷态资格；未知效果先核 journal；同类有限重试耗尽即阻断，保留完整恢复点 |
| 存储 admission 再失败 | 当前峰值与完整未来封套不匹配 | qsub 前用已采用卡和实际关闭成本核算；不靠减保护或未授权删除通过 |
| source 学生能力不足 | 两任务完整成功低、合法后段失败集中 | 报 SOURCE_POLICY_LIMITED；只选择一个有证据的学习干预 |
| 目标一直停留在 CPU 准备 | 没有新实际 prefix／ACK／STOP／task 回执 | 给最小未接线 delta；设原时钟出口，源域继续 |
| 接口实验混入软件修复收益 | 两臂 frame／TCP／数值或安全路径不同 | 共同修复并冻结新 cohort，历史不重写 |
| R1 与数据同时变化 | 新 normalizer＋新库同时替换 | 拆共同支持 codec 对照与固定 R1 coverage 对照 |
| 推理 noise 被当训练 seed | rollout 增多但权重只训练一次 | 分层统计，分别报告，不夸大独立样本数 |
| 目标数据污染主张 | target 示范、性能调参或预测器适配进入训练 | 单列 calibrated／target-adapted，零目标主比较保持干净 |
| WM／planner 只有多算收益 | K 增大但未与等 K 基线比较 | 同候选同成本对照；无独立收益就停止该分支 |
| 最终评估被工程挤占 | 完整未来对照预算不够 | 停新候选和可选 stress；保留最终保护，交部分或负结果 |
| 反复重新命名延长战役 | 旧 clock／失败／费用在新卡消失 | 原记录保持，新 scope 显式衔接；禁止滚动重置 |
| 安全失败 | 原生限位／接触／状态或停止链错误 | 立即停受影响执行，取证并走独立重资格；不放宽门槛 |

有效任务失败、正常 S1 拒绝与工程未知不能混为一类。正常策略失败应计入结果，工程未知应保留并遵守有限替代，真实安全失败触发对应执行停止。

## 15. 统一交付包与研究结束条件

每个主阶段形成一个可审查的结果包，复用既有格式：

- **科学报告**：预声明假设、实际干预、保持项、适用域、原始计数、配对区间、失败、未知和未运行条件。
- **行为矩阵**：task／geometry／noise／training seed／executor／interface；完整成功、拒绝、完整目标失败、工程缺失与 attempt lineage。
- **模型与数据卡**：权重、processor、normalizer、action schema、父模型、实际消费、源执行器、目标适配量和合法输入。
- **执行证据索引**：真实观测→query→raw action→installed reference→installation ACK→获准 physics→实际反馈／prefix execution ACK→下一观测；controller／plant／runtime／frame／time 身份。
- **资源终局**：实际 GPU／CPU／PBS／更新／查询／物理／存储／传输、丢失更新、原生作业和租约关闭。
- **复现入口**：依赖锁、固定私有工件 revision、离线加载／schema 与批准仿真入口；默认不触发真机。
- **主张清单**：OBSERVED、SUPPORTED_WITH_LIMITS、HYPOTHESIS、NOT_RUN；规划辅助、模拟 oracle、纯学生和蒸馏结果分别命名。

每个阶段都允许完整负结果或诚实部分结果作为终局。只有证据达到既定级别才升级主张。一次 seed、一个机器人资产、两条任务指令、零实际 fault 或训练完成均不足以支撑通用、实时或部署安全声明。

当前战役结束时应能明确回答：A/B 是否完整，新增覆盖是否有可解释收益；目标能否执行本轮策略；核心解耦实验完成多少以及为何未完成；哪些费用换来了可保留的模型与可审查的结果。后继 8–12 周计划再由这些答案决定唯一优先科学干预。
