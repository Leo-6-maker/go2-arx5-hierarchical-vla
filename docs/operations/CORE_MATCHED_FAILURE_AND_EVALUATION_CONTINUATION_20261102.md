复用现有native关闭程序、Journal和onceIO，不另建资源账本或调度平台。`native_outcome.py`核实原生进程终态、准确manifest/lease、RESULT、实际生成次数／数组文件以及journal费用。仅已核清的模型训练失败、无物理的诊断失败、零条件零物理的模型前评价失败可走这条关闭路径。已发生物理的评价仍走原始输入—参考—命令—原生评分审计；实际安全STOP、有效条件和未运行数不改。

结果分为执行生命周期、副作用关闭、科学结果三个字段。零模型／零生成的容量拒绝可为CLOSED，但不能成为96次推理资格通过。真正UNKNOWN、缺终态、活动子进程、身份改变或费用不明时不自动关闭和重放。

GPU1仅为可选加速器。未来冷态配置同时检查GPU1与GPU0：GPU1未就绪而GPU0满足原24GiB入口和RAM条件时，使用GPU0原评价入口；GPU1须有同一checkpoint的独立native96容量资格。所有项目模型加载仍串行。连续空闲观察不是排他分配，启动时原生容量检查保持。

当前封存manager不热改。若完成生产者收尾后仅在等待GPU1，可在确证的冷态边界转移其未启动后继：限定本项目PID/proc_start/Invocation和封存身份，短暂暂停manager以重核等待状态、无子进程、全部metadata步骤完成、全部原生角色终态且CLOSED；不满足则立即原样恢复。满足后仅终止空闲manager，不触碰已关闭或运行中的GPU worker；取得准确终态和唯一owner后才运行新接续。该机制通过测试不等于已在现役manager发生交接，实际挂载／交接另留回执。
