# Existing Night10 native continuation bindings

The scoped-writer repair passed a new Core native zero-integration qualification:
12 source constructors, eight dual-camera pairs, independent pristine/dirty
state checks, actual live/UNKNOWN/residual writer refusals and registered PID reuse
refusal. Its lease is CLOSED. The earlier failed qualification remains intact.
The new certificate is not a completed policy condition. DOOR's two PNG encodings
were not identical; each actual image hash was independently read back and both
passed the original camera requirements. Bitwise renderer equality is not added
as a scientific criterion.

`native_relay.py` supplies task commands to the existing Night10 supervisor. It
uses the original raw/shared learner, book evaluator, source scorer, registry,
onceIO, transient user units and GPU locks. It adds no optimizer, model, simulator,
scoring implementation, usage ledger or replacement scheduling platform.

The private immutable binding fixes six BOOK producer identities in order:
Phase4096, D0, D1, D2, PB_CONTROL and PB_BOUNDARY. A policy needs its own CLOSED
full4096 checkpoint and 42-state restore. A missing producer is BLOCKED_NOT_RUN,
not a zero-success result or a reason to select qualification weights. At a cold
boundary, the exact available checkpoint headers determine the new reset panel;
the predeclared six candidates and absent candidates remain in the outer graph.
There is one native96 inference qualification per eligible model, followed by at
most its ten original conditions in ten new registered processes. An actual
native safety stop is retained as a valid negative. Each successor verifies
original initial/camera/close witnesses and actual process/writer closure before
constructing its own engine. Earlier partial panels are not continued or rescored.

The independent raw branch uses original common59 and raw7 inputs: native10
with full42/AdamW/scheduler/RNG/sampler restore, independent raw native16 inference,
then one fresh task8:8:8:8 shared8192. Each branch uses its own same-GPU certificate.
BOOK certificates never authorize raw training. GPU1 remains protected for M13;
GPU0 work must satisfy original capacity, real host RAM, storage and neural owner
custody. The live M13 capsule is immutable and no job is duplicated or preempted.

The readonly monitor tests the existing neural owner lock and independently
checks staged actors, leases and canonical UNKNOWN effects. Scientific failure
is not a requirement to wait: a CLOSED known failure permits independent work.
An active worker after loss of its manager still blocks new model loading.
CPU audits do not take that neural lock. They verify trusted raw stat identities,
expert numeric bytes, all68 DEV references, saved joint4 evidence and each exact
131072-draw D2/PB sequence without fitting statistics or importing Torch.

A formal8192 accepted within the ten-hour new-dispatch window transfers to its
own finite resident controller and native unit. Adoption requires actual matching
PID/start/InvocationID and a held owner lock. A zero exit from that dispatch is
only adoption, never training completion. Its own bounded training/restore may
finish after the dispatch window; the Night10 manager does not kill it at ten
hours. New conditions or experiments are not admitted after the window.

The existing supervisor always writes its terminal summary, including resource
waits and unknown effects. The readonly monitor also writes a readable current
summary with actual D2 progress and per-task receipts. Private raw media and
checkpoints stay on their existing node-local paths. No cleanup, host permission,
service configuration, NFS, SSH, credentials, WBC or target quarantine change is
part of this binding.

Validation before adoption: 120 targeted CPU checks passed, including actual
sealed M13 control-flow fixtures (separate proof) and adapter boundary checks for
missing/full restores, retained active actors, unknown/excess counts, altered
native records, ambiguous closure and duplicate run identity. These are not native
raw GPU qualification. Full resident deployment requires independent Core
registration, code/config/plan digests, actual unit identity, two disconnected
heartbeat observations and a concrete task/RESOURCE_WAIT receipt.
