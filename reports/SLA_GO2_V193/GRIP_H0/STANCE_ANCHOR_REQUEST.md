# V1.9.3 G01 步态触发归因与站立 H0 后继申请

G01 在固定底座参考下于 23.140 s 切换步态。冻结腿策略读到的三分量底座命令范数从 0.09998586 到 0.10004907，跨过原程序门限 0.1，步频由 0 变成 2.75 Hz。触发周期的三个输入分量与一条真实 WBC 底座消息逐值相符。腿部策略输出经原缩放后，和 tick 11,571–11,578 实际消费的 PD 目标吻合，最大误差 4.5×10⁻⁸ rad。这是入场后的唯一一次非零步频周期。最新任务参考此时已生效 0.234 s，仍在原 0.4 s 有效期内。 [归因回执](G01_STANCE_CAUSE_CPU.json)

触发前，左前脚最大位移为 1.246 mm。随后首个积分 tick 的脚底法向力从 53.09 N 降至 2.82 N。在消费该腿部输出的 16 ms 内，左前脚越过原 5 mm 门，峰值脚中心速度达到 443.1 mm/s。同期 TCP 仅移动 0.346 mm。观测支持从底座命令越门、腿部目标变化到站姿门触发的执行链。原任务中固定的底座目标与实测入场底座存在约 21.4 mm、2.85° 的差。这个参考偏差是否促成命令越门仍需原生对照。

## 唯一改动

按原程序预热和稳定后，读取同一暂停时刻的 MPC 估计底座位姿，选为之后固定的世界系 BASE 参考。继续使用已经消费的世界系 EEF，保持开爪，等待至少 500 tick 且重新通过原 501 点稳定性检查，随后执行原教师。站姿位移仍相对首次稳定时的真实脚位、机身位置和姿态检查，贯穿换参考、等待以及任务。保留冻结 WBC、腿策略、力矩、支持与接触门，保留原 5 mm 站姿门和 0.1 步态切换门。回放只验证参考和检查逻辑。 [候选预检](STANCE_ANCHOR_CPU.json) · [运行绑定](STANCE_ANCHOR_OWNER_CPU.json)

这一操作在 G01 水果场景的真实暂停状态上通过了原 40 点 EEF 预览与 41 点 BASE 格式检查。G00 使用旧无接触 Reach 的稳定入场实测作为预检载体。两者都保留了原已消费的 EEF，固定底座参考的改变量分别为 21.434、21.439 mm。旧 D1 的 OM 条件使用同类单次 BASE 重设，五张匹配卡中观测到早期 TCP 约 1 mm 下移。D1 测量适用原场景和 1 s 时间窗。 [历史 OM 对照](../../SLA_MEMORY_D1_MATCHED/README.md)

## 科学分配

候选顺序为 G01 后 G00，每布局一次 MuJoCo 教师启动，每卡独立租约，每卡最多 50,000 个 2 ms tick，合计最多 100,000 tick。除固定底座参考的选取时机外，沿用 #502 两个水果布局、原教师、原接收器、原评分和两处三视角观测事件。若 G01 出现技术中止或安全停止，关闭该卡并保留 G00 未启动。完整完成条件为正确物体抓持、抬升至少 20 mm 和连续保持至少 1 s。旧两卡结果保留，G00 的旧启动问题与 G01 的旧步态触发分别记录。模型前向、训练更新和额外硬件执行均为 0。

当前仅通过 CPU 预检。候选执行需要此次独立科学分配。学生仍需相应布局的新教师资格、三相机观测与真实源物理工具标定。
