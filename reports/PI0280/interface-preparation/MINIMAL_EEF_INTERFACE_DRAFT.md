## Recommendation and current evidence

After PI0280 source/WBC evidence is reviewed and a new decision permits adaptation, first consider **one EEF-only NEW_EMBODIMENT interface**, training only its `state_encoder`, `action_encoder`, and `action_decoder` row while freezing the entire VLM and shared action trunk. This is an architecture-supported hypothesis, not an established successful adapter. Keep the original 132-dimensional padded architecture, 40-step horizon, and four denoising steps; use the existing official relative SE(3) conversion. Do not create another control representation or copy a source projector into a supposedly pretrained target route.

| `action_encoder` | W1 W `[32,132,1536]`, b `[32,1536]`; W2 W `[32,3072,1536]`, b `[32,1536]`; W3 W `[32,1536,1536]`, b `[32,1536]` | 7,285,248 |

`CategorySpecificLinear.forward` indexes W/b by category (`embodiment_conditioned_mlp.py:59–79`); the encoder adds a deterministic time encoding, not another learned target parameter (`177–225`). The state history is one step; input embedding is 1536, shared DiT output is 1024, VLM features are 2048. The checkpoint selects 32-layer AlternateVLDiT and four-layer VL self-attention. These widths come from headers/checkpoint values plus official config defaults, not a model instance.

**Stock flags are insufficient for row-only training.** `Gr00tN1d7ActionHead.set_trainable_parameters` (`gr00t_n1d7.py:121–168`) initially enables all head parameters. `tune_projector=True` leaves all 32 rows of the three projectors **and** shared `position_embedding.weight [1024,1536]` trainable: **327,356,544** scalars, including **1,572,864** shared position parameters. `tune_diffusion_model=False` freezes `action_head.model`, and `tune_vlln=False` freezes both `vlln` and `vl_self_attention`; freezing only “VLM + DiT” would omit those shared modules. The candidate must also freeze positions, every non-target row, and all backbone parameters, with frozen modules in eval mode.

Future implementation must enforce **actual updates only on row 10**, then prove other rows/shared tensors byte-identical after a bounded update. Packed tensors have no row-level `requires_grad`; gradient masking alone does not stop optimizer weight decay or old momentum. A minimal packed-tensor implementation needs explicit row gradient masks, zero decay on these packed tensors, fresh optimizer state, and readback of every frozen row. Report both packed tensors admitted to the optimizer (325,783,680 scalars if whole packed projectors are used) and allowed-to-change row scalars (10,180,740); do not misreport whole-tensor `requires_grad` as 10M. A row-only parameter representation would require a separate reviewed implementation and checkpoint conversion. None is implemented here.

Freezing the shared trunk means freezing its parameters and dropout behavior while **retaining autograd through the trunk to the state/action encoder inputs**. Wrapping the frozen DiT forward in `no_grad` would sever encoder learning; VLM feature extraction can be detached because no candidate gradients need to reach its inputs. A later bounded training admission must verify nonzero finite gradients for all three candidate modules, frozen-parameter immutability, and the stock masked loss. No gradient was computed in this review.

## Target binding, initialization, and masking

The official processor assigns `new_embodiment` to **row 10**, sharing that placeholder with RoboCasa tags (`processing_gr00t_n1d7.py:58–120`). The base's serialized modalities/statistics contain eight pretrain tags and omit `new_embodiment`; the enum explicitly labels NEW_EMBODIMENT finetune-only (`embodiment_tags.py:217–224`). A packed row existing in the checkpoint is not evidence of trained Go2 semantics. Future artifacts must bind the effective processor mapping, not infer it from a legacy tag name or standalone mapping file. Do not mix placeholder aliases in one training dataset.

Proposed initialization for a future isolated adaptation artifact: keep all genuine original shared weights, initialize only row 10 with the official category-linear rule (W normal scaled by 0.02, b zero; `embodiment_conditioned_mlp.py:62–67`), and record seed/hash plus `UNTRAINED_TARGET_INTERFACE`. Keeping serialized row 10 unchanged could be an alternative initialization only if explicitly bound and labelled as a placeholder of unverified training history. Neither initialization has occurred. Copying DROID row 24 would be an additional learned mapping intervention with different joint/normalization semantics; it is excluded from this first proposal. Any later trained result is **minimal target interface adaptation**, never a genuine zero-shot target pretrained route.

| `action.gripper_width` | Absolute executable width `[40,1]`, `ABSOLUTE / NON_EEF / DEFAULT`; no source gripper coordinate assumed equivalent. |

Policy state/action slices are `[0:9]` EEF and `[9:10]` gripper; the 122 remaining dimensions are **structural padding of this newly declared 10D contract**. They do not stand in for missing source joints. No joints/body/hand/object poses enter the policy; these may be simulator diagnostics for safety/scoring only. EEF-only feedback might still be insufficient for reachability, body motion or contact observability; that limitation is a testable hypothesis, not cured by fabricated source state.

Freeze a proposal-native 15 Hz high-level data grid (period 1/15 s), two images at offsets `[-15,0]`, state `[0]`, action indices `0..39`, and stock image/language processing. This is a declared **new interface data cadence**, not a claim that DROID cadence is native to WBC. All raw timestamps must be retained; nearest/interpolated alignment is allowed only by a declared causal sensor contract. Native WBC timing remains unchanged. Row 10 needs new interface state/action/relative-action statistics: fit only admitted source-bound training windows after separate authorization, serialize/hash them, and retain base route statistics unchanged. No new statistics have been fitted.

Official relative conversion uses the last raw state (`state_action_processor.py:363–394,473–524`), with absolute reconstruction `T_abs=T_anchor@T_relative` (`action_chunking.py:624–658`). Decode once, then fixed task-to-WBC/TCP transforms; no second relative transform, velocity scaling, or tuned task offsets. Nonidentity rotations and moving-anchor cases require future roundtrip checks against the official processor; quaternion/rot6d row/column conventions remain a binding gate.

**Mask counterevidence:** training pads state/action to 132 and masks action loss beyond the semantic dimensions (`processing_gr00t_n1d7.py:597–668`); the loss mask appears after the forward (`gr00t_n1d7.py:228–278`). Noise is sampled over **all 132 action dimensions**, the action encoder consumes them all, and inference performs four full-dimensional updates without applying an action-dimension mask (`349–353,396–435`). Masking loss does not make unused channels causally irrelevant. For the first stock-semantics proposal retain the same padding/noise path in train/inference, record actual full initial noise, and test sensitivity to changing only padded noise in a later authorized audit. Reject unexpected coupling if it defeats the frozen repeatability contract; do not silently clamp channels or change the forward. A clamp would be another intervention requiring a new decision.

## Small shared dataset proposal — no collection performed

Start with **pick-place + stack** in an independently bound physical task/tool environment; target-WBC complete success is not a collection or retention prerequisite. Expand to place-in-container and push-to-region only if requested before collection; one shared interface and one shared policy throughout, with each source/target domain's fixed calibration disclosed. Reach remains optional bounded controller qualification and is excluded from the main object-task training counts. Twenty training, five validation and ten sealed test demonstration episodes per task are proposed: 70 episodes for two tasks or 140 for four. Collection is capped at 35 physical starts/task including failures; insufficient interface-valid windows may leave less usable data and do not open replacement collection. These are small pilot caps, not adequacy estimates. Each episode is at most 32 s; retain all failures and admission exclusions in an inventory.

Admit **source-bound, interface-valid windows from successful and failed episodes**: synchronized real RGB, actual achieved EEF/gripper feedback, coherent timestamps, finite semantically valid teacher references, declared physical contact/safety and unchanged processor/gate checks. Include valid pre-failure/recovery windows with explicit episode/window failure labels and causes in the audit namespace. A failed grasp, release or target-WBC episode is not itself an exclusion; corrupted observations, ambiguous/unsafe labels or missing history are window-specific exclusions with recorded reasons. Independent teacher task correctness can be checked, but a failed execution must not be relabelled as a successful demonstration or trained against an incorrect reference merely to keep data. Admission never asks whether the target WBC completed the task.

Episode/schema requirements: immutable episode/task/split/group/source-domain IDs; real RGB file hashes and sensor timestamps; actual achieved source-tool TCP/gripper and state timestamps; raw teacher reference, source gate decision, source installed reference and commanded/achieved gripper stored separately; future source-validated installed task EEF/width labels with timestamps; fixed source frame/tool/camera/controller/scene hashes, separately bound target-WBC identity when evaluated; teacher provenance; explicit episode/window failure labels, causes and admission reasons; contacts, object state and task predicates in a scoring-only namespace. Source-tool feedback is actual feedback, never claimed to be actual Go2 feedback. Source/target camera/tool domain differences remain disclosed transfer risks. If a different action-label definition is desired, decide it before collection and do not mix intended references with achieved future poses. Use existing dataset loader conventions; this document adds no new dataset implementation or examples pretending to be observations.

Split by whole demonstration groups (object instances, placement families, scene/calibration/session); neighbouring frames and the same trajectory never cross splits. Fix group IDs before outputs. Preserve PI0280 conditions as developed diagnostics; do not turn them into sealed generalization evidence or open reserved held-out conditions. For two tasks sample each with probability 1/2; for four use 1/4. Then sample an episode uniformly and a valid causal anchor uniformly, with real history and all 40 label timestamps. No padding a truncated tail into “valid” labels. Keep instructions fixed; no outcome-based prompt edits or adaptive task mixing. Derive normalization only from admitted training groups once.

## Future comparison, caps, and stopping criteria

These numbers are **proposed ceilings for a new decision**, not PI0280 counters/permissions:

| Comparison | Role and limit |
|---|---|
| Existing PI0280 original source model + source physics | Evidence of source behavior; domain differs and cannot substitute for target feedback. Reuse sealed results. |
| Frozen target WBC + expert EEF per task | Execution feasibility control, 4 developed conditions/task once. A controller/scene blocker prevents interpreting a target closed-loop score as pure policy quality; it does not invalidate independent task data or shared task-reference learning. No WBC/scene/gate tuning between comparisons. |
| Untrained target interface + genuine frozen trunk | Explicitly untrained target negative control: 4 developed conditions/task once; failures are expected evidence, never a zero-shot pretrained score. Same initialized row/statistics as the trained candidate. |
| Row-10-only adaptation + genuine frozen trunk | Single first learning hypothesis; one fixed initialization, same tasks/data, stock flow-matching objective, no loss/seed/checkpoint sweep. |
| Row 10 + shared DiT at low learning rate | **Deferred second hypothesis**, only after first result review and another decision. No budget inherited. |

Proposed first learning cap: **2,048 optimizer updates total**, batch 16, accumulation 1 (32,768 sampled chunks), including any canary; a 512-update engineering pilot is part of that total. One GPU, at most 4 GPU-hours; completion/stop at the first cap. Fixed optimizer/schedule/learning rate must be specified by the next authority before execution; source inspection cannot justify a numerical optimum. One final update-count checkpoint for the task panel; validation is diagnostic and does not select a better test checkpoint. No automatic extension for failure.

Proposed per-domain evaluation panel for two/four tasks: expert 4 + untrained 4 + trained developed 4 + trained sealed test 10 = **22 starts/task**, at most **44/88 evaluation starts**, no valid-failure retries. Evaluate high-level object-task learning first in the same independent physical task/tool domain as the source data; separately evaluate execution with the frozen target WBC. Neither domain replaces the other. If both panels are authorized, evaluation caps are **88/176 starts**, and including 35 source demonstration-collection starts/task the total simulation-start cap is **158/316**. Each episode is at most 32 s and 60 policy requests at the proposed 15 Hz/8-sample replanning contract. Max neural policy requests per domain are **2,160/4,320**; both domains together **4,320/8,640**, each four head evaluations. All retries/warmups consume these caps. Physical controller/control/actor/gripper/pre-roll budgets must be calculated from each bound domain's actual dt/decimation before any future launch, with zero hardware commands. No launch is possible from this incomplete draft.

Use unchanged, physically defined success predicates fixed before collection: pick-place means object released on the designated support and inside the fixed goal region with stable contact for 2 s; stack retains the original StackCube predicate at all 41 samples 28–30 s; container means released object entirely in the fixed interior, settled under a prebound velocity criterion for 2 s; push-to-region means the designated object reaches the fixed region through physical contact and remains settled there for 2 s. Optional reach qualification means position <=2 cm and SO(3) angle <=10 degrees for every terminal sample over 2 s, with no claim of object-task learning. Geometric region/velocity/settling thresholds for new tasks need scene-specific binding before collection; no ad hoc values are promoted here. All require original safety limits and no fall/collision/limit termination. Safety or gate failure stays in the evaluation denominator; infrastructure/contract blockers are reported separately.

Proposed execution feasibility goal: expert >=3/4 per task plus no severe safety violation, reported per domain. It is not a training-data admission gate. Proposed small-panel candidate goals: >=3/4 developed and >=8/10 sealed test per task, reported separately for independent source-tool task learning and target frozen-WBC execution, with exact fractions and binomial uncertainty. These are engineering goals, not validated universal scientific thresholds. A target controller/scene limitation can leave target composition unestablished while source task-reference learning remains assessable under its own separately authorized panel; neither result automatically opens training or a new hypothesis. Target interface execution additionally requires at least three genuine fresh target queries and two reference replacements responding to changed achieved feedback; task success alone cannot hide reference playback. Preserve raw -> gated -> installed -> achieved -> object attribution and actual gripper throughout.

Success would show that the frozen pretrained shared modules can participate in this declared target adaptation. It would not isolate the causal benefit of pretraining, establish embodiment-unaware generalization, or authorize hardware. A causal pretrained-prior claim needs a separately authorized matched randomized/fresh-trunk control, beyond this first minimal experiment. A failure does not automatically justify VLM tuning: inspect feasibility, calibration/history, padding/noise coupling and observation sufficiency before deciding whether shared-DiT adaptation is warranted.
