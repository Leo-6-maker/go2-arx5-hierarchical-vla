# B1 · 时间窗和持续参考的 CPU 一致性试验

在教师执行环境的 Python 中调用归档管理器和现场版本化接收器的实际回调，使用安装版本的 ROS 消息类型序列化并反序列化输出。时间、测量位姿和状态为合成输入；发布目标由进程内记录器接收。使用单独的运行目录。全程无在线 ROS 节点、WBC 安装、求解器调用和原生积分。

| 检查 | 实测结果 |
|---|---|
| 归档窗口格式 | 默认 2 秒、50 ms，含两端共 41 点。加入位于 0.373 s 的非网格拐点后为 42 点。EEF 状态按 xyz＋四元数 xyzw 排列，7 维；附底座时 14 维。每点 12 维目标输入全零。 |
| 坐标、空路径与模式 | 已验证 world、world_offset、ee_start 的已知坐标结果。归档拒绝空路径并保留原参考。禁用状态发布实测位姿的单点 HOLD；重新使能后旧路径未自动恢复。 |
| 归档重复发送整条路径 | 对 10 mm/s 的合成直线，首次在 MPC 时间 10.0 s 绑定，每 0.5 s 重发旧全文。到 12.0 s，单次绑定首段目标速度仍为 +10 mm/s，重复绑定为约 −390 mm/s，最远目标差 20 mm。这里测量的是目标消息。 |
| 现场接收器 | 只接受当前 episode 的下一序号、世界系、41 点、50 ms、零 lead-in、0.4 s TTL 的安装包。正常接收年龄范围为 0–25 ms。提前不超过 25 ms 到达的包等待匹配观测。负例覆盖旧序号、过期包、未使能、相对坐标包与非标准长包。 |
| P10 仅发一次 | 在 10.000 s 接受的包，10.399 s 仍有效，收到 10.400 s 观测时请求 HOLD。下个 P10 为 10.500 s，晚 100 ms。单次安装的原始两秒预览未提供两秒控制权。 |
| 时钟倒退 | 合成 MPC 时钟从 10.1 s 回到 9.8 s 后，当前绑定起点仍为 10.0 s，现场回调生成了 9.8 s 起始窗口且未请求 HOLD。重新绑定前需要独立处理时钟代次和过期参考。 |
| 10 秒直线的持续发布 | 用同一条长 100 mm 的世界系参考比较两种上层行为：只确定一次意图，或每个 P10 更新同一路径的未来剩余段。两组都由管理层每 100 ms 提供接收器要求的窗口。各输出 101 个目标，所有时间、状态和输入字段的数值及类型编码逐项相同；两组各请求 0 次 HOLD。 |

最后一组的最大拼接位置差约 1.48×10⁻⁸ m，源于消息中的 float32 位置精度。对比使用完整字段。首次加强比对时，整段 ROS CDR 字节流的散列不同；继续核对后，观察到的差别只在首个 float64 序列前的对齐填充字节，所有有定义字段的编码均相同。另一次早期运行在写入摘要时遇到 NumPy 标量序列化失败，两次技术中断均计入运行日志。

**B1 的结论。** 经现场接收器允许的格式，持续发布完整运动的未来部分，在这条已知参考上能够传达连续目标。后续上层管理器应持有完整意图和执行时间轴，将 P10 的未来修订、在 TTL 内刷新传输、求解器的优化时域分别管理。对时钟回退需要清除旧代次并取得新的合法状态；夹爪另需 owner、已消费命令与 ACK。本轮的双时钟对照只验证了消息级行为，未给出 TCP 实际误差、控制器能力范围或抓放结果。

B2 为 `NOT_RUN / WAIT_FOR_AUTHORIZED_NATIVE`。下一项物理试验需先明确时钟异常停机、现场租约、逐卡 tick 与独立授权。B3 正式接口资格依赖 B2 的跟踪测量，B4 冻结策略配对还需学生合法拥有夹爪。新 GPU 调用、物理请求、积分 tick 与训练更新均为零。[V1.4 协议](../../docs/protocols/SLA_MEMORY_V14_BACKEND_SPECIFIC_REFERENCE_MANAGER_PLAN_20261123.md)
