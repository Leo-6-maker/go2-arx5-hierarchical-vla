# Prospective execution freeze

Bind scripts/pi0255_motion3.py, scripts/pi0255_collect.py, scripts/pi0255_run.py and task_registry_v1.json at the accompanying immutable commit before the first real simulator step. Issue #11 canonical publication precedes execution_seal.json and execution.

The registry contains all geometry, factor order, splits, language assignments, seeds, durations, expert profiles, terminal holds, scoring predicates, exposure caps and window admission rules. CPU fixtures cover correct and wrong commands, direction/order, forbidden contact, reference-only hits, SE(3), timestamp/timeout and privileged input rejection through the actual NPZ/JSON loader.

The dispatcher defaults to validation-only, invokes the actual native entry point's harmless help path, and has no VLA training path. --pilot requires PI0255_MULTITASK_GENERALIZATION_READINESS_GO_V1. Each expert episode is a separate process. Existing first valid results are reused; an engineering exception stops dispatch for minimal repair rather than automatic repeated physics.

The collector counts the actual first WBC step, including env.reset's implicit zero-action step, before it occurs. It preserves the inherited controller, gains, physics, camera mounts, reference hot-swap lifecycle, state/action ABI and gate. Registered construction/settling references are explicit, not outcome-dependent perturbations. All actual task/gate/physical failures remain valid results.

Actual reset state/image/RNG identity, same-tick tracking, whole-scenario split leakage, observability, every-window codec/gate, usable phase coverage and model compatibility are later evidence requirements. CPU fixtures do not certify those real outcomes.
